# AGENTS.md — контракт для агента, который открыл репозиторий впервые

Ты пишешь код в Symbiosis V7. Этот файл — всё, что нужно, чтобы взять задачу и
не наломать дров. Читай целиком до первого коммита.

**Документация в репозитории — на русском. Код, идентификаторы, ветки,
сообщения коммитов, PR — на английском.**

---

## 1. Что это за проект

Offline-first LAN-приложение с **единственным авторитетным хостом**. Роли:
`player`, `gm`, `system`. Целевая платформа — Windows 10 (1809+) / 11 x64.

Проект строится **от поставленных артефактов**, а не от кода. В `artifacts/`
лежат 12 файлов: шесть предметных реестров в xlsx, атлас UI в json+md,
замороженный Runtime Pack и манифест поставки. Всё игровое содержимое —
формулы, пороги, названия, ограничения — берётся оттуда.

Ключевое следствие: **игровые данные не придумываются**. Нет значения в
артефакте — остановись и заведи issue, см. раздел 8.

## 2. Команды

Требуется Node.js `>=24.19.0 <25` (см. `.nvmrc`) и npm `>=11`.

### Первый запуск после клона — именно в таком порядке

```bash
npm ci
npm run import
npm run verify
```

**`npm run import` обязателен.** `generated/media` не хранится в git
([ADR 0016](docs/adr/0016-what-generated-is-committed.md)) — его создаёт импорт.
Запустишь тесты раньше, получишь:

```
Error: ENOENT: no such file or directory, scandir '…/generated/media/items'
```

Это не поломка репозитория. Это пропущенный шаг.

**Компилятор не нужен.** В `package.json` есть поле `allowScripts`, где сборка
`better-sqlite3` запрещена поимённо — без этого `npm ci` уходит в node-gyp и
требует Visual Studio Build Tools и Python. Увидел `gyp ERR!` — не устанавливай
Build Tools, проверь `allowScripts`.

**Добавил зависимость с install-скриптом — CI остановится**, пока по ней нет
решения в `allowScripts`. Это не придирка: скрипт установки выполняется на
машине разработчика с его правами. Разрешаешь — напиши в PR, зачем он нужен и
что делает.

| Команда                           | Что делает                                                               |
| --------------------------------- | ------------------------------------------------------------------------ |
| `npm run verify`                  | **главная проверка**: суммы → типы → линтер → формат → тесты → валидация |
| `npm run import`                  | `artifacts/` → `generated/`                                              |
| `npm run validate`                | кросс-реестровая валидация `generated/spec`                              |
| `npm run checksums:verify`        | проверить артефакты на дрейф                                             |
| `npm run checksums`               | пересчитать `artifacts/CHECKSUMS.sha256`                                 |
| `npm run typecheck`               | `tsc` по node- и web-проектам                                            |
| `npm run lint` / `lint:fix`       | ESLint                                                                   |
| `npm run format` / `format:check` | Prettier                                                                 |
| `npm test`                        | vitest                                                                   |
| `npm run test:e2e`                | Playwright                                                               |

Перед push обязана проходить:

```bash
npm run verify
```

`validate` входит в `verify`; отдельно запускают, когда меняют только данные.

**Портативной сборки пока нет.** `tools/package` — пустой каталог. Не пытайся
её запускать и не выдумывай команду.

**E2E пока нет.** Конфиг Playwright настроен, тестов нет, браузеры не
установлены. `npm run test:e2e` проходит только потому, что тестов ноль. Первый
реальный e2e-тест потребует `npx playwright install chromium`.

## 4. Границы: что нельзя менять без согласования

Каждый пункт — стоп-сигнал. Наткнулся — не чини, заведи issue.

| Граница                   | Файлы                                                                        | Почему                                                                                            |
| ------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Артефакты**             | `artifacts/**`                                                               | Read-only источник правды. Изменение ломает SHA-256 и всю трассируемость                          |
| **Контрольные суммы**     | `artifacts/CHECKSUMS.sha256`                                                 | Перегенерировать можно **только** если артефакт поставлен заново и это подтверждено владельцем    |
| **Вывод конвейера**       | `generated/**`                                                               | Производится `tools/import`. Правка руками будет затёрта следующим прогоном                       |
| **Решения проекта**       | `docs/adr/**`                                                                | Принятый ADR не редактируется по существу. Изменение решения — новый ADR                          |
| **CI**                    | `.github/**`                                                                 | Меняется отдельным PR с обоснованием                                                              |
| **Конфигурация проверок** | `eslint.config.js`, `tsconfig*.json`, `.prettierrc.json`, `vitest.config.ts` | Ослабление проверки ради прохождения задачи запрещено                                             |
| **Концы строк**           | `.gitattributes`                                                             | `artifacts/** -text` держит побайтовую неизменность. Снятие ломает `checksums:verify` после клона |

### Отдельно: правила, застрахованные кодом

В `tools/import` есть проверки, которые сверяют ADR с их источником в
артефактах. Они **намеренно** остановят импорт, если артефакт изменится:

- `assertAdr0004` — множитель `FREE` = 2, начисление опыта необратимо
- `assertAdr0011` — ровно один немоделируемый эффект, `EFF-SENSE-BLINDNESS`
- `assertAdr0007Contract`, `assertTemplateInvariants` — `NO_XP_PROGRESSION`
  у всех 44 системных шаблонов

Если такая проверка упала — это **не баг проверки**. Либо поставлен новый
артефакт, либо что-то не так. Ослаблять проверку нельзя.

## 5. Соглашения по коду

TypeScript strict, ESM, Node 24. Импорты относительных путей **с расширением
`.js`** (`module: NodeNext`).

### 5.1 Отказ вместо догадки

Неизвестное значение, отсутствующий лист, незнакомый статус — **отказ с
указанием того, что именно не распознано**. Никаких generic fallback,
никакого «похоже на X, обработаем как X», никакого молчаливого no-op.

Пример из [tools/import/lib/workbook.ts](tools/import/lib/workbook.ts):

```ts
sheet(name: string): Sheet {
  const raw = this.#book.Sheets[name];
  if (raw === undefined) {
    fail(
      this.#label,
      `sheet ${JSON.stringify(name)} not found; available: ${this.#book.SheetNames.join(', ')}`,
    );
  }
  // …
}
```

Ошибка называет и то, чего не нашли, и то, что было доступно. Так отладка не
требует запуска отладчика.

### 5.2 Комментарий объясняет «почему», а не «что»

Пример из [tools/import/lib/media.ts](tools/import/lib/media.ts):

```ts
/**
 * Pairing images with rows by sorting `xl/media/` would be wrong twice over:
 * the names sort lexicographically (`image10.png` before `image2.png`), and
 * nothing guarantees that upload order matches row order.
 */
```

Код показывает, что делается. Комментарий нужен там, где неочевидно, **почему
не сделано проще**.

### 5.3 Величины из артефакта, а не из головы

Пример из [tools/import/rules.ts](tools/import/rules.ts):

```ts
/**
 * Control values the audit states about this registry: CHK-001 739 cards,
 * CHK-002 699 active. The remaining 40 are tombstones.
 */
const EXPECTED = { cards: 739, active: 699, tombstone: 40 /* … */ } as const;
```

У каждой константы есть источник. Число без источника в ревью не проходит.

### 5.4 Именование

- Файлы и каталоги — `kebab-case`
- Типы и классы — `PascalCase`, функции и переменные — `camelCase`
- Константы-инварианты — `UPPER_SNAKE_CASE`
- Формы UI ссылаются на ID атласа: `APP-001`, `CMB-014`
- Папки `src/web/forms/` названы префиксами ID: `app`, `cmb`, `chr`…

### 5.5 Импорты

Относительные пути — **с расширением `.js`**, даже для `.ts`-файлов
(`module: NodeNext`):

```ts
import { fail } from './lib/fail.js';
```

Общий код и сгенерированное — через алиасы:

```ts
import type { FormId } from '@generated/types/atlas.js';
import { FORM_IDS } from '@generated/types/atlas.js';
```

Алиасы объявлены в трёх местах и должны совпадать: `tsconfig.base.json`
(типы), `vitest.config.ts` (тесты), `vite.config.ts` (сборка web). Добавляешь
новый — добавляй во все три, иначе он пройдёт `typecheck` и упадёт в рантайме.

### 5.6 Где лежат тесты

`src/**/*.test.ts` и `tools/**/*.test.ts` — рядом с кодом. Файл в корне
репозитория **не попадает ни в один проект vitest и молча не запускается**.

## 6. Инкрементальность

**Одна задача = минимальный diff. Полная пересборка приложения запрещена.**

- Не переписывай работающий модуль, чтобы «сделать красивее»
- Не меняй стиль в файлах, которых не касается задача
- Не добавляй зависимости без ADR
- CI отклонит PR, превышающий разумный объём — см.
  [.github/workflows/pr-size.yml](.github/workflows/pr-size.yml)

Лимиты считаются раздельно, потому что 2000 строк документации — обычный PR,
а 2000 строк кода — переписывание:

|                     | Лимит |
| ------------------- | ----: |
| Код: строк          |   900 |
| Код: файлов         |    25 |
| Тесты: строк        |   700 |
| Документация: строк |  3000 |
| Всего файлов        |    60 |

Тесты вынесены в свой бюджет по той же причине. Пока они считались как код,
строка теста стоила ровно столько же, сколько строка реализации, — то есть
хорошее покрытие приближало отказ guard'а наравне с переписыванием модуля.
Пороги откалиброваны по замеру первых задач, а не назначены: реализация
укладывалась в 566–662 строки, тесты — в 193–331.

Тестом считается файл `*.test.ts` / `*.test.tsx` (и `.spec.`), а также всё
под `tests/`.

`generated/` не считается вовсе — это вывод конвейера, а не ручная работа.

Считаешь, что нужна большая переделка — **заведи issue с обоснованием**, не
делай её попутно.

## 7. Ветвление и PR

- `main` защищён. Прямой push запрещён
- Ветки: `codex/<issue>-<кратко>` и `claude/<issue>-<кратко>`
- Одна ветка — один агент. Не коммить в чужую ветку
- Жизнь ветки — **не более 2 дней**. Дольше — дроби задачу
- Merge делает **только владелец репозитория**. Squash merge

### Definition of Done

PR готов, когда выполнено **всё**:

- [ ] Тесты написаны и зелёные
- [ ] `npm run verify` проходит локально
- [ ] Обновлён `docs/TRACEABILITY.md`, если изменилось покрытие
- [ ] Запись добавлена в `CHANGELOG.md`, раздел **«Не выпущено»**
- [ ] Обновлён `docs/status/module-map.md`, если изменилось состояние модуля
- [ ] CI зелёный
- [ ] Незакрытые места помечены маркерами (раздел 9)

### Если менял артефакт-зависимое

Изменил `tools/import` или поставлен новый артефакт — прогони импорт и
**закоммить пересобранный `generated/`**:

```bash
npm run import && git add generated/
```

CI сверяет, что после прогона импорта рабочее дерево чистое. Забыл
закоммитить — шаг «Pipeline output is reproducible» упадёт.

Оформление PR — по [шаблону](.github/pull_request_template.md).

## 8. Конфликт кода с артефактом

Если код требует значения, которого нет в артефакте, **или артефакт
противоречит коду**:

1. **Остановись.** Не подставляй правдоподобное значение
2. **Не правь артефакт под код.** `artifacts/` read-only
3. Заведи issue по шаблону, укажи: какой артефакт, какой лист, какой ID,
   в чём противоречие
4. Продолжай с другой задачей

Порядок источников правды — [ADR 0003](docs/adr/0003-source-of-truth-order.md).
Коротко: `docs/adr/` → `docs/` → манифест поставки → предметные реестры →
атлас и Soundtrack → Q&A → Runtime Pack → отчёт аудита.

## 9. Маркеры незавершённого

Единый формат, чтобы дыры были видны из репозитория:

```ts
// TODO(M3): подключить реестр handler'ов, см. docs/backlog/0003-*.md
// STUB(M2): заглушка до появления схемы БД
// BLOCKED(artifact): значения нет в реестре, issue #NN
```

- `TODO(<веха>)` — запланировано, веха указана
- `STUB(<веха>)` — есть заглушка, работает не по-настоящему
- `BLOCKED(<причина>)` — упёрлось во внешнее решение

Маркер без вехи или причины CI не пропустит.
