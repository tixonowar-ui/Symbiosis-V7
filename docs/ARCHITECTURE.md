# Архитектура

> Заготовка. Описывает принятую структуру и границы слоёв. Детали протокола,
> схемы БД и рендерера появятся по мере реализации — выдуманного здесь нет.

## Форма приложения

Offline-first LAN-приложение. Один процесс — **хост** — владеет состоянием и
является единственным авторитетом. Клиенты подключаются к нему по локальной
сети и отображают то, что хост разрешил их роли видеть.

```
┌─────────────────────────────────────────────┐
│  host (единственный авторитет)              │
│                                             │
│  Fastify ── статика + HTTP                  │
│  ws ────── канал состояния по ролям         │
│                                             │
│  projections/  player │ gm │ system         │
│        │                                    │
│        ▼                                    │
│  domain/  rules + 19 entity lifecycles      │
│        │                                    │
│        ▼                                    │
│  persistence/  SQLite (better-sqlite3)      │
└─────────────────────────────────────────────┘
                    ▲  LAN
                    │
     ┌──────────────┴──────────────┐
     │  web (renderer по атласу)   │
     │  376 форм, 16 доменов       │
     └─────────────────────────────┘
```

## Слои и зависимости

Зависимости направлены строго вниз:

| Слой              | Знает о                           | Не знает о                     |
| ----------------- | --------------------------------- | ------------------------------ |
| `src/shared`      | ничём из слоёв                    | обо всех                       |
| `src/domain`      | `shared`                          | БД, сети, UI                   |
| `src/persistence` | `shared`, типы домена             | сети, UI, правилах             |
| `src/host`        | `shared`, `domain`, `persistence` | внутренностях UI               |
| `src/web`         | `shared`                          | БД, правилах, файловой системе |

`src/domain` чистый: без `fs`, без сети, без SQL. Это делает правила
тестируемыми и переносимыми.

## Роли

Определены атласом:

| Роль     | Полномочия                                                                      |
| -------- | ------------------------------------------------------------------------------- |
| `player` | только допущенные локальные места и проекции игрока, безопасные для наблюдателя |
| `gm`     | авторитет хоста; отдельная проекция мастера и административные команды          |
| `system` | серверные handler'ы, принудительные триггеры, неинтерактивные спецификации      |

## Проекции

Проекция строится **на хосте**. То, что роли не положено видеть, не
отправляется — а не скрывается на клиенте. Обратное было бы утечкой, которую
видно в трафике.

Атлас определяет 10 guard-состояний, влияющих на проекцию: `role`, `authority`,
`controllerSeat`, `scene/phase`, `stateRevision`, `projectionRevision`,
`actorVisibilityRevision`, `resource/effect/equipment`,
`consent/masterPredicate`, `connection`.

Три ревизии — `stateRevision`, `projectionRevision`, `actorVisibilityRevision` —
образуют контракт переподключения: клиент после обрыва догоняет состояние по
ревизии, а не перезагружает всё.

## Конвейер artifacts → generated

```
artifacts/            read-only, в git
  registries/  10 xlsx
  atlas/       Web UI Screen Atlas v1.2 (json + md)
  packs/       Runtime Pack v1.2 (zip)
  CHECKSUMS.sha256
        │
        ▼  tools/import
generated/            только вывод, руками не править
  spec/   формы, правила, journeys   (в git)
  types/  TS-типы                    (в git)
  seed/   SQLite seed                (НЕ в git)
  media/  арты и иконки              (НЕ в git)
```

Целостность источника проверяется `npm run checksums:verify` и обязана
проходить перед коммитом.

## Правила

Из Executable Rules Registry v1.7: **699 активных правил**, **40 tombstone**,
**70 операций**, **106 workflow-команд**, 167 автоматизированных способностей,
66 моделируемых типов эффектов, 15 узлов только для ручной обработки.

Tombstone-правило — явный отказ, а не пробел. Оно зарегистрировано и отклоняет
вызов с причиной.

## Fail-closed

Неизвестная команда, workflow, тип эффекта, переход или форма **отклоняются**.
Нет ветки по умолчанию, нет обработки «по аналогии», нет тихого no-op. Отказ
называет то, что не распознано.

## Целостность и трассируемость

- `docs/TRACEABILITY.md` — снимок покрытия по вехам, генерируется
  `tools/traceability`
- Каждая форма ссылается на ID из атласа в коде и в тестах
- Каждый тест правила ссылается на ID правила из реестра
