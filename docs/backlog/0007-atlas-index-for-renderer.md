# 0007 — Индексы атласа под рендерер, вместо дословной копии

- Веха: **M5**
- Размер: средняя
- Метки: `task`, `M5`
- **Зависит от 0001** — индекс по ID делается там

## Контекст

`generated/spec/atlas` — 10,9 МБ, из них `forms.json` 8,4 МБ. Это 0,84 от
исходного json атласа, то есть почти дословная копия. Признано временным
решением в [ADR 0016](../adr/0016-what-generated-is-committed.md) с прямым
указанием пересмотреть на M5.

Когда появится generic-рендерер, ему нужны не «все формы массивом», а адресный
доступ: форма по ID, переходы по `from`, journeys по форме.

## Критерии приёмки

- [ ] Определено и записано в ADR, какие индексы нужны рендереру — **на основе
      того, что он реально запрашивает**, а не по догадке. Если рендерера ещё
      нет, задача ждёт: проектировать индексы под несуществующего потребителя
      не нужно
- [ ] `generated/spec/atlas` перестаёт хранить дословную копию `forms`
- [ ] Ни один атрибут формы, используемый рендерером, не потерян — проверяется
      тестом на полноту, а не глазами
- [ ] Объём `generated/spec/atlas` сокращается; фактическая цифра — в PR
- [ ] Импорт остаётся детерминированным
- [ ] ADR 0016 дополнен записью о том, что избыточность закрыта

## Затрагиваемые модули и ID

- `tools/import/atlas.ts`
- `tools/validate/index.ts`
- `src/web/renderer` — потребитель
- ID: все 376 форм, 1672 перехода, 66 journeys

## Чего касаться нельзя

- `artifacts/**` — атлас остаётся источником в неизменном виде
- Проверки целостности атласа при импорте

## Как проверяется результат

```bash
npm run import && npm run verify && npm run validate
```

## Замечание

Не начинать, пока рендерер не показал, какие запросы ему нужны. Оптимизация
хранения под воображаемого потребителя — это и есть преждевременная
оптимизация; в проекте, где источник правды заморожен, она обойдётся дороже
обычного.
