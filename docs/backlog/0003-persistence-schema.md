# 0003 — Схема БД и первая миграция

- Веха: **M2**
- Размер: большая — **разбить на подзадачи перед взятием**
- Метки: `task`, `M2`

## Контекст

`src/persistence/` — заглушка. Схемы БД нет, поэтому `generated/seed` пуст и
перенесён с M1 на M2.

Схема выводится из `generated/spec`, а не проектируется с нуля. Сущности уже
известны: 19 `entityLifecycles` из атласа, каталоги предметов, эффектов,
бестиария и системных врагов.

**Перед реализацией нужен ADR** на модель хранения: одна таблица на сущность
против event sourcing, как хранится ревизия состояния, как ложатся 19
жизненных циклов. Это решение, а не деталь реализации.

## Критерии приёмки

- [ ] ADR принят и описывает модель хранения с альтернативами
- [ ] `src/persistence/migrations/0001-initial.ts` — первая миграция
- [ ] Миграции нумерованные, применяются по порядку, **только вперёд**
- [ ] Повторное применение на актуальной схеме ничего не делает
- [ ] Тест проходит путь с нуля до актуальной версии
- [ ] Тесты работают с БД в памяти (`:memory:`), файлов в репозитории не
      создают
- [ ] Слой не содержит игровых правил — только хранение
