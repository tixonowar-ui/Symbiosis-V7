# 0006 — Реестр handler'ов правил, каркас

- Веха: **M3**
- Размер: средняя
- Метки: `task`, `M3`

## Контекст

`src/domain/rules/` пуст. Нужен каркас реестра: механизм регистрации и
диспетчеризации, **без реализации самих правил**. Правила пойдут отдельными
задачами, по группам.

Ключевое свойство — реестр **не имеет ветки по умолчанию**. Неизвестная команда
отклоняется с указанием того, что не распознано.

Отдельно: 40 tombstone-правил. Они уже выгружены как
`TOMBSTONE_RULE_IDS` в `generated/types/rules.ts`. Tombstone — не пробел, а
явный отказ: реестр обязан отвечать «правило `X` существует и не
автоматизируется», а не «правила нет». Разница между этими двумя ответами и
есть смысл задачи ([ADR 0011](../adr/0011-not-modeled-stays-tombstone.md)).

## Критерии приёмки

- [ ] Реестр принимает регистрацию handler'а по `RuleId` из
      `generated/types/rules.ts`
- [ ] Попытка зарегистрировать handler на ID вне каталога — ошибка компиляции
      (тип `RuleId`), а не проверка в рантайме
- [ ] Попытка зарегистрировать handler на tombstone-правило — отказ
- [ ] Вызов незарегистрированного активного правила — отказ с указанием ID
- [ ] Вызов tombstone-правила — отказ **иного вида**, сообщающий, что правило
      существует и не автоматизируется
- [ ] Двойная регистрация одного ID — отказ
- [ ] Ветки по умолчанию нет ни в одном `switch`
- [ ] Слой остаётся чистым: без `fs`, сети, SQL
- [ ] Тесты покрывают все четыре вида отказа

## Затрагиваемые модули и ID

- `src/domain/rules/`
- ID: 699 активных и 40 tombstone, см. `generated/types/rules.ts`

## Чего касаться нельзя

- `artifacts/**`, `generated/**`
- Реализация конкретных правил — это отдельные задачи

## Как проверяется результат

```bash
npm run verify
```

## Источник в артефактах

`generated/spec/rules/rules.json` и `generated/types/rules.ts`. Тексты правил
на этом этапе не интерпретируются — только их наличие, статус и ID.
