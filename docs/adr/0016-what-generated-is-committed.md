# ADR 0016 — Что из `generated/` хранится в git

- **Статус:** принято
- **Дата:** 2026-08-08

## Контекст

`generated/` целиком производится `tools/import`. Вопрос — что из этого
попадает в репозиторий.

Величины на момент решения:

| Каталог           |   Объём |         Файлов |
| ----------------- | ------: | -------------: |
| `generated/spec`  | 26,8 МБ |            115 |
| `generated/types` |  0,1 МБ |              7 |
| `generated/media` | 22,5 МБ |            124 |
| `generated/seed`  |       — | пусто, веха M2 |

Плюс сам `artifacts/` — 66,7 МБ, тоже в git.

## Решение

- `generated/spec`, `generated/types`, `generated/seed` — **в git**
- `generated/media` — **не в git**, исключён в `.gitignore`

## Обоснование

### Почему spec и types коммитятся

Сборка не должна требовать прогона конвейера. Клонировал — собрал.
`generated/types/*.ts` участвует в `typecheck`, и без него репозиторий просто
не компилируется.

Второе, менее очевидное: эти файлы **диффятся**. Новая поставка артефактов
показывает в PR ровно то, что изменилось в машинном виде, — а не «обновлён
xlsx на 900 КБ». Для проекта, где артефакт есть источник правды, это главный
инструмент ревью поставки.

### Почему media не коммитится

124 изображения, 22,5 МБ, и они не диффятся: бинарный файл в PR показывает
только факт изменения. При этом каждое из них уже покрыто SHA-256 — либо
объявленным в реестре (Sentient), либо через `CHECKSUMS.sha256` на
артефакт-источник. Хранить их вторым экземпляром в истории git незачем:
`npm run import` восстанавливает их побайтово (ADR 0015, гарантия детерминизма).

### Признанная избыточность

`generated/spec/atlas` — 10,9 МБ, из них `forms.json` 8,4 МБ. Это 0,84 от
исходного `Web_UI_Screen_Atlas_v1.2.json`, то есть почти дословная копия,
отличающаяся сортировкой ключей и форматированием. Добавленная ценность
сегодня — валидация при импорте и стабильный дифф.

Это принято **временно**. На вехе M5, когда появится generic-рендерер,
`generated/spec/atlas` должен превратиться из копии в индексы под него: формы
по ID, переходы по `from`. Тогда дублирование уйдёт само, и отдельного решения
не потребуется.

## Альтернативы

- **Не коммитить `generated/` вовсе** — отвергнуто: ломает сборку без прогона
  конвейера и лишает ревью дифференциального взгляда на поставку.
- **Коммитить и media тоже** — отвергнуто: +22,5 МБ бинарников в историю без
  выигрыша в проверяемости.
- **Git LFS** — отвергнуто на текущем объёме: добавляет обязательный шаг
  установки на машине разработчика, что противоречит простоте offline-first
  сборки. Пересмотреть, если `artifacts/` перевалит за ~200 МБ.

## Последствия

- Первый `git clone` тянет около 95 МБ. Это заметно, но однократно.
- После клона обязателен `npm run import`, иначе `generated/media` пуст.
  Отсутствие медиа не ломает `verify` — тесты медиа читают то, что произвёл
  импорт, и запускаются после него.
- PR, меняющий артефакт, обязан содержать пересобранный `generated/spec`.
  Расхождение поймает CI: он прогоняет импорт и сверяет, что рабочее дерево
  чистое.
- На M5 пересмотреть содержимое `generated/spec/atlas`.
