# ADR 0010 — Лимит локальных мест

- **Статус:** принято
- **Дата:** 2026-08-01 (перенесено в ADR 2026-08-07)
- **Источник:** Cross-Registry Audit Report v1.2 — AUD-015

## Контекст

Фиксированный лимит локальных игроков не был задан (AUD-015), из-за чего
поведение при добавлении мест оставалось неопределённым.

## Решение

**0–3 вкладки игрока** на устройство и **отдельная вкладка мастера**.

Нормативное основание: baseline device limit. Атлас, страница 268. Результат
проверки — лимит задан явно.

## Обоснование

Решение перенесено из аудита без изменений.

Вкладка мастера считается отдельно и не расходует лимит игроков — это разные
сущности, а не четвёртое место.

## Последствия

- Нижняя граница — **0**: устройство без вкладок игрока допустимо (например,
  устройство мастера или наблюдателя).
- Попытка открыть четвёртую вкладку игрока **отклоняется** явно, с указанием
  лимита. Не молчаливое игнорирование и не вытеснение существующей вкладки.
- Entity lifecycle `deviceAndLocalSeat`
  (`src/domain/entities/device-and-local-seat`) владеет этим правилом.
- Формы домена `NET-` (подключение и полномочия) отражают лимит в UI, но
  проверка выполняется на хосте: клиентская проверка здесь подсказка, а не
  защита.
