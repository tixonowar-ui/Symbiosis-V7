# ADR 0001 — Целевые платформы

- **Статус:** принято
- **Дата:** 2026-08-06

## Контекст

Приложение offline-first и работает в локальной сети: один авторитетный хост и
подключённые к нему клиенты. Нужно зафиксировать, на каких версиях Windows это
поддерживается, чтобы решения о рантайме и нативных зависимостях принимались
осознанно, а не выяснялись при первом отказе у пользователя.

## Решение

Поддерживаются:

- **Windows 10, сборка 1809 и выше, x64**
- **Windows 11, x64**

Не поддерживаются:

- **Windows 7** — снят с поддержки
- Windows 8 / 8.1, Windows 10 до 1809
- 32-разрядные сборки (x86) и ARM64

## Обоснование

Windows 7 не поддерживается потому, что современные JS-рантаймы его не
поддерживают. Node.js прекратил поддержку Windows 7 и Windows 8.1 начиная с
Node 18; Node 20 и новее требуют Windows 10 версии 1809 либо Windows Server
2019 как минимум. Проект работает на Node 24 LTS
([ADR 0002](0002-stack.md)), поэтому нижняя граница определяется рантаймом, а
не нашим выбором.

Обходных путей нет: собрать проект под Windows 7 можно было бы только откатом
на давно неподдерживаемый Node без обновлений безопасности. Это неприемлемо.

Ограничение x64 отражает фактическую цель поставки. Нативная зависимость
`better-sqlite3` поставляет готовый бинарник `win32-arm64` наравне с
`win32-x64`, так что ARM64 технически достижим, но не заявляется как
поддерживаемый, пока не появится сценарий и возможность это проверить.

## Последствия

- `package.json` объявляет `"os": ["win32"]` и `"cpu": ["x64"]`.
- `engines.node` фиксирует диапазон Node 24 — см. [ADR 0002](0002-stack.md).
- Инструмент упаковки (`tools/package`) собирает portable-сборку под x64.
- Проверка версии ОС при запуске хоста должна быть явной и понятной: на
  неподдерживаемой системе — внятный отказ, а не падение в середине работы.
