# ADR 0014 — Чтение артефактов в конвейере импорта

- **Статус:** принято
- **Дата:** 2026-08-07

## Контекст

`tools/import` должен читать 10 xlsx-реестров, атлас (json) и Runtime Pack
(zip), чтобы собрать `generated/`. Требования жёстче обычных:

- **Детерминизм.** Одинаковый вход обязан давать побайтово одинаковый выход
  (M1 в [ROADMAP](../ROADMAP.md)).
- **Offline-first.** Никаких загрузок и нативной сборки при установке
  ([ADR 0002](0002-stack.md)).
- **Не только ячейки.** Из книг извлекаются вложения `xl/media/`: 64 иконки в
  Item Registry и 16 артов в Бестиарии (CHK-010, CHK-011). Библиотека, отдающая
  только таблицу, эту задачу не закрывает.

## Решение

Две зависимости:

| Пакет        | Версия | Назначение                                     |
| ------------ | ------ | ---------------------------------------------- |
| `@e965/xlsx` | 0.20.3 | разбор ячеек xlsx                              |
| `fflate`     | 0.8.3  | сырой доступ к ZIP: `xl/media/` и Runtime Pack |

Обе — без транзитивных зависимостей, обе поставляют собственные типы
TypeScript. `npm audit` после установки: 0 уязвимостей.

## Обоснование

### Почему не `xlsx` (SheetJS с npm)

Пакет `xlsx` в npm заморожен на `0.18.5` (март 2022): проект перенёс
распространение на собственный CDN. За ним числятся две уязвимости высокой
критичности — prototype pollution (уязвимы `<0.19.3`) и ReDoS (уязвимы
`<0.20.2`). Обе покрывают версию, доступную в npm.

`node-xlsx` отвергнут по той же причине: он обёртка над этим же `0.18.5` и
наследует обе уязвимости.

`@e965/xlsx` — форк SheetJS, опубликованный в npm в версии `0.20.3`, то есть
выше обоих уязвимых диапазонов, и без транзитивных зависимостей.

### Почему не `exceljs`

Умеет и ячейки, и изображения, но последний релиз — октябрь 2023, девять
транзитивных зависимостей, и для Runtime Pack всё равно понадобился бы
отдельный ZIP-пакет.

### Почему не собственный парсер OOXML

Вариант с одним `fflate` и разбором `sharedStrings`/листов вручную даёт
максимум контроля, но переносит на нас краевые случаи формата — даты, числовые
форматы, inline strings. Ошибка там проявляется как **тихо неверное значение**,
а не как отказ, что прямо противоречит fail-closed принципу проекта
([CLAUDE.md](../../CLAUDE.md), раздел 5).

## Проверено на реальных артефактах

Обе библиотеки сверены с контрольными величинами самого аудита:

| Проверка аудита                | Ожидается | Получено |
| ------------------------------ | --------: | -------: |
| CHK-004 строк Q&A              |       444 |      444 |
| CHK-005 уникальных кодов Q&A   |       410 |      410 |
| CHK-010 иконок в Item Registry |        64 |       64 |
| CHK-011 артов в Бестиарии      |        16 |       16 |
| CHK-013 файлов в Runtime Pack  |        50 |       50 |

Дополнительно: Rules v1.7 читается как 15 листов (совпадает с манифестом),
кириллические заголовки и значения не искажаются, SHA-256 из манифеста
считывается посимвольно, числовые поля приходят как `number`.

## Последствия

- Конвейер обращается к книгам через `@e965/xlsx`, к архивам — через `fflate`.
  Смешивать назначения не нужно: у каждой библиотеки своя роль.
- Лист выбирается **по имени**, а не по индексу. У реестров первый лист — как
  правило «Сводка», и чтение по индексу молча вернёт не те данные: на Q&A это
  даёт 24 строки вместо 444.
- Отсутствие ожидаемого листа, колонки или вложения — **отказ импорта**, а не
  пустой результат.
- Импорт сверяет `artifacts/CHECKSUMS.sha256` до чтения: артефакт, не прошедший
  проверку, не обрабатывается.
- При обновлении `@e965/xlsx` проверять, что версия остаётся выше `0.20.2` —
  ниже начинаются известные уязвимости SheetJS.
