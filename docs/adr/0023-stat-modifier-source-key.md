# ADR 0023 — источник модификатора задаётся парой `SourceType` + `SourceID`

- **Статус:** Принято
- **Дата:** 2026-08-10
- **Источники:** Character / Skills / Symbionts Registry v1.2 — листы
  `02_Расы`, `03_Классы`, `06_Модификаторы_персонажа`, `18_Справочники`;
  Executable Rules Registry v1.7 — карточки `CORE-001`, `CORE-006`,
  `CORE-008`, `CORE-009`, `CORE-010`, `CORE-013`

## Контекст

Для перехода `baseStats → skillStageStats`, определённого как
`base + race + class` в `18_Справочники!A94:E95`, нужно найти расовые и
классовые модификаторы. Character Registry одновременно поставляет две
группы похожих на адресацию полей, но не описывает связь между ними:

- расы и классы содержат `StatModifierProfileID`, а классы дополнительно
  `ContextModifierRefs` (`02_Расы!F5:F8`, `03_Классы!F5:G8`);
- нормализованная таблица модификаторов не содержит profile ID. Её заголовок —
  `ModifierID`, `SourceType`, `SourceID`, `TargetKind`, `TargetCode`,
  `Operation`, `Value`, `ContextPredicate`, `ApplicationStage`, `StackPolicy`,
  `Rule IDs`, `ID unique` (`06_Модификаторы_персонажа!A5:L5`), данные занимают
  ровно 43 строки (`A6:L48`).

Независимый прогон через принятый [ADR 0014](0014-artifact-reading.md) пакет
`@e965/xlsx` проверил все 26 листов книги. Значения `RACE-MOD-*` встречаются
только в `02_Расы!F6:F8` и их payload-копиях `20_Payload_JSON!D13:D15`;
`CLASS-MOD-*` — только в `03_Классы!F6:G8` и payload-копиях `D16:D18`.
Заголовки `StatModifierProfileID` встречаются только в `02_Расы!F5` и
`03_Классы!F5`, `ContextModifierRefs` — только в `03_Классы!G5`. Прогон не
нашёл в книге словаря или таблицы, которая объявляет эти значения внешним
ключом; среди 151 строки `18_Справочники!A6:E156` таких ID нет. Формулы
`06_Модификаторы_персонажа!L6:L48` проверяют только уникальность `ModifierID`
через `COUNTIF`.

Импорт не потерял поля или строки: записи листов `02_Расы`, `03_Классы` и
`06_Модификаторы_персонажа` были программно сравнены поле в поле с
[`races.json`](../../generated/spec/character/races.json) (`RaceCode`,
`StatModifierProfileID`, `Creation Rule IDs`),
[`classes.json`](../../generated/spec/character/classes.json) (`ClassCode`,
`StatModifierProfileID`, `ContextModifierRefs`, `Rule IDs`) и
[`modifiers.json`](../../generated/spec/character/modifiers.json) (все 12 полей
из заголовка выше). Совпали соответственно 3 из 3, 3 из 3 и 43 из 43 записей.
Значит, исправлять `tools/import` или `generated` нельзя: неоднозначность
присутствует в самом поставленном реестре.

### Проверенные группы

Поля `SourceType` и `SourceID` разбивают все строки модификаторов без остатка:

| Группа источника       | Строк | Ячейки модификаторов | Независимое подтверждение                                                                                                                                     |
| ---------------------- | ----: | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RACE / FREE`          |     3 | `A6:L8`              | `K6:K8 = CORE-006`; раса ссылается на `CORE-006` в `02_Расы!I7`, а значения совпадают с `Реестр правил!P5:R5`                                                 |
| `RACE / UNITED`        |     8 | `A9:L16`             | `K9:K16 = CORE-001`; раса ссылается на `CORE-001` в `02_Расы!I8`, шесть creation- и две context-дельты совпадают с `Реестр правил!P2:R2`                      |
| `RACE / PURE`          |     0 | нет в `B6:C48`       | `02_Расы!C6,I6` требует класс через `CORE-008/009/010/013`; `Реестр правил!P445:R445` требует выбрать один класс и применить соответствующую классовую группу |
| `PURE_CLASS / SEEKER`  |     6 | `A17:L22`            | `K17:K22 = CORE-009`, `03_Классы!H6 = CORE-009`, значения совпадают с `Реестр правил!P7:R7`                                                                   |
| `PURE_CLASS / STALKER` |     6 | `A23:L28`            | `K23:K28 = CORE-010`, `03_Классы!H7 = CORE-010`, значения совпадают с `Реестр правил!P8:R8`                                                                   |
| `PURE_CLASS / SOLDIER` |     6 | `A29:L34`            | `K29:K34 = CORE-013`, `03_Классы!H8 = CORE-013`, значения совпадают с `Реестр правил!P9:R9`                                                                   |

У `UNITED` именно восемь строк: три `RANDOM`, три `MANUAL` и две
`CHECK_CONTEXT` (`06_Модификаторы_персонажа!A9:L16`). Остальные 14 из 43 строк
принадлежат `SYMBIONT_PROFILE` и имеют `ApplicationStage = EFFECTIVE_STATS`
(`I35:I48`); их применение не входит в переход `skillStageStats`.

`SourceID` совпадает с каноническими кодами: `RaceCode` перечислен в
`18_Справочники!A13:E15`, `PureClass` — в `A16:E18`, `SymbiontSpecies` — в
`A64:E86`. Все 43 строки разрешаются в соответствующем словаре. Отдельного
словаря `SourceType` среди 151 строк `18_Справочники!A6:E156` нет.

Карточки Executable Rules и Character Registry стоят на одном уровне порядка
источников [ADR 0003](0003-source-of-truth-order.md). Они не спорят: поля
источника, словарные коды, `Rule IDs` и численные алгоритмы сходятся. Но ни одна
карточка буквально не объявляет внешний ключ и не говорит «расовая поправка
PURE равна нулю». Эти две недостающие интерпретации принимает данный ADR.

## Решение

### 1. Источник строки определяется точной парой

`ModifierID` остаётся уникальной идентичностью одной строки. Пара
`(SourceType, SourceID)` — **неуникальный селектор группы**: один источник
закономерно имеет несколько модификаторов.

Для поставки v1.2 действует закрытое отображение:

| `SourceType`       | Словарь для `SourceID` | Область решения                                                                             |
| ------------------ | ---------------------- | ------------------------------------------------------------------------------------------- |
| `RACE`             | `RaceCode`             | расовые строки, включая `SKILL_STAGE` и `CHECK_CONTEXT`                                     |
| `PURE_CLASS`       | `PureClass`            | классовые строки; `SourceID` равен `ClassCode`                                              |
| `SYMBIONT_PROFILE` | `SymbiontSpecies`      | только проверка идентичности источника; применение `EFFECTIVE_STATS` данным ADR не решается |

Выбранная раса с кодом `X` получает группу ровно
`(SourceType = RACE, SourceID = X)`. Выбранный класс Чистого с кодом `X` —
группу ровно `(SourceType = PURE_CLASS, SourceID = X)`.

После выбора группы применимость каждой строки определяется отдельно и точно
по `ApplicationStage` и `ContextPredicate`. Группа класса содержит также
`CHECK_CONTEXT`, но переход `baseStats → skillStageStats` применяет только
строки `ApplicationStage = SKILL_STAGE`. Приближённое совпадение стадии или
предиката запрещено. Строка другой **известной** стадии просто неприменима на
текущем переходе; точный поддержанный предикат с результатом `false` также не
применяет строку. Неизвестная стадия или неподдержанная грамматика предиката —
отказ, а не неприменимость.

### 2. Висячие поля не разыменовываются в v1.2

`StatModifierProfileID` и `ContextModifierRefs` переносятся из артефакта
дословно, но не участвуют в выборе строк и не нормализуются. В частности,
запрещено переставлять токены `RACE-MOD-* → MOD-RACE-*` или
`CLASS-MOD-* → MOD-CLASS-*`.

Такая перестановка действительно восстанавливает префиксы пяти групп, имеющих
строки, — `FREE`, `UNITED` и трёх классов — и точные `ModifierID` всех шести
context-ссылок (`02_Расы!F7:F8`, `03_Классы!F6:G8` против
`06_Модификаторы_персонажа!A6:A34`). Но она нигде не объявлена контрактом и не
разрешает `RACE-MOD-PURE` из `02_Расы!F6`. Систематичность похожих имён —
свидетельство дефекта адресации, а не разрешение строить runtime-ключ из
строки.

Решение ограничено поставкой v1.2. Если новая поставка добавит каталог этих
profile/ref ID или сделает их точно разрешимыми, потребитель останавливается до
пересмотра этого ADR; он не продолжает молча игнорировать уже определённую
связь.

### 3. Пустая расовая группа разрешена только для `PURE`

Точный результат выбора `(RACE, PURE)` — пустая расовая группа. Для этого
единственного кортежа пустота означает нулевой **расовый** вклад, после
которого обязателен ровно один класс и его группа `PURE_CLASS` по `CORE-008`.
Отсутствующий класс остаётся отказом, а не нулевым классовым вкладом.

Это не общее правило `нет строк = ноль`. Для любой другой расы или класса
неожиданно пустая группа означает дрейф контракта и даёт отказ. Появление строк
`(RACE, PURE)` также требует пересмотра решения: оно больше не совместимо с
зафиксированной здесь семантикой пустой группы.

Пустота группы проверяется **до** фильтрации по стадии и предикату. Уже
существующая группа может законно дать ноль применимых строк в конкретном
контексте: у `RACE / FREE` все три строки требуют `creationMode=MANUAL`
(`06_Модификаторы_персонажа!H6:I8`), а `CORE-006` прямо задаёт отсутствие
расовой поправки для `random` (`Реестр правил!R5`). Это ложный предикат, а не
потерянная группа.

### 4. Неизвестное отклоняется fail-closed

Каталог модификаторов проверяется до вычисления:

- `SourceType` вне трёх значений закрытого отображения отклоняется с указанием
  самого значения;
- `SourceID`, которого нет в словаре, соответствующем его `SourceType`,
  отклоняется с указанием пары и ожидаемого словаря;
- `SourceID` без `SourceType`, префикс `ModifierID`, `Rule IDs`,
  `StatModifierProfileID` и `ContextModifierRefs` не используются как
  резервные ключи.

Новый `SourceType` не принимается даже тогда, когда его `SourceID` совпал с
кодом существующего словаря. Сначала требуется явное отображение типа на его
словарь и пересмотр границы решения.

Этот ADR не вводит общую грамматику `ContextPredicate`. Потребитель явно
перечисляет точные предикаты своей стадии: поддержанный предикат с результатом
`false` не применяет строку, а неизвестная стадия или неподдержанный предикат
дают отказ.

## Обоснование

Пара использует два поля, которые сама таблица называет типом и ID источника.
Она не требует разбирать имя строки. Точное совпадение кодов со словарями
задаёт namespace, а `Rule IDs` и карточки правил независимо подтверждают
владельца и каждую из 29 численных расовых и классовых дельт
(`06_Модификаторы_персонажа!G6:G34`). Это достаточно, чтобы принять узкое
проектное решение без восстановления отсутствующей механики.

Отсутствие `RACE / PURE` согласуется с межреестровыми свидетельствами:
`ClassPolicy = REQUIRED_PURE_CLASS` и набором class rule ID в одной строке
`02_Расы!C6,I6`, а также обязательным маршрутом через `CORE-009/010/013` в
другом реестре — `Реестр правил!R445`. ADR не выдаёт этот вывод за дословную
фразу артефакта и не распространяет его на другие пустые группы.

Отвергнутые альтернативы:

| Вариант                                                      | Почему отклонён                                                                                                                                                                                                  |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Разыменовать profile/ref ID точно                            | Ни один из шести `StatModifierProfileID` (`02_Расы!F6:F8`, `03_Классы!F6:F8`) и ни один из шести элементов `ContextModifierRefs` (`03_Классы!G6:G8`) не равен `ModifierID` из `06_Модификаторы_персонажа!A6:A48` |
| Переставлять `RACE-MOD`/`CLASS-MOD` в `MOD-RACE`/`MOD-CLASS` | Работает для `02_Расы!F7:F8` и `03_Классы!F6:G8` против `06_Модификаторы_персонажа!A6:A34`, но это неописанная строковая эвристика; `PURE` из `02_Расы!F6` всё равно остаётся без цели                           |
| Соединять по `Rule IDs`                                      | Для `PURE` коды из `02_Расы!I6` выбирают сразу 18 строк трёх взаимоисключающих классов в `06_Модификаторы_персонажа!K17:K34`                                                                                     |
| Соединять только по `SourceID`                               | Глобальная уникальность кодов разных словарей не объявлена; `SourceType` потерял бы смысл и будущая коллизия молча изменила бы владельца                                                                         |
| Любой пустой результат считать нулевым                       | Превращает потерянную или новую группу в допустимый путь; данный ADR разрешает только специально разобранный случай `(RACE, PURE)`                                                                               |
| Ждать исправленный артефакт                                  | Допустимо при недостаточном свидетельстве, но здесь прямые поля источника, словари, `Rule IDs` и карточки правил сходятся без противоречия; ожидание блокировало бы уже определённую механику                    |

## Последствия

- Issue #39 получает однозначный, fail-closed способ выбрать расовые и
  классовые строки для `skillStageStats` без строковых эвристик.
- `artifacts/**`, `generated/**` и `tools/import/**` не меняются. Висячие поля
  остаются видимыми в точной копии поставки.
- Реализация обязана различать идентичность строки, группу источника и
  применимость по стадии/контексту; соединение группы само по себе не означает
  применение всех её строк.
- Область поправки намеренно узкая: v1.2, известные source namespace и один
  разрешённый пустой кортеж. Следующее расхождение или новая схема адресации
  требуют отдельного решения, а не расширения эвристики.
