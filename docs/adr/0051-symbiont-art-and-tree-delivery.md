# ADR 0051 — Поставка арта симбионтов и изображений деревьев развития

- **Статус:** принято
- **Дата:** 2026-10-26
- **Дополняет:** [ADR 0014](0014-artifact-reading.md),
  [ADR 0015](0015-import-pipeline-guarantees.md) и
  [ADR 0016](0016-what-generated-is-committed.md)
- **Реализует:** issue #139 после поставки исходных mapping-книг в #143

## Контекст и источники

`CHR-018` требует `artAndTreePreview`, но до этой поставки конвейер не извлекал
арт симбионтов и изображения деревьев. Машинная структура развития уже есть в
`generated/spec/character/development-nodes.json` (182 узла); отсутствовали
именно изображения, а не игровые связи.

Issue #143 поставил два файла:

- `artifacts/symbiont-media/Symbiosis_V7_Symbiont_Art_Mapping_v1.0.xlsx`,
  лист `SymbiontArt`;
- `artifacts/symbiont-media/Symbiosis_V7_Symbiont_Development_Tree_Mapping_v1.0.xlsx`,
  лист `DevelopmentTrees`.

Каждая книга содержит строку заголовка, 23 строки с явным `SpeciesKey` и
`FileName`, 23 изображения с якорями OOXML и 23 части в `xl/media`. Это отдельная
additive delivery к исходной поставке v1.2, а не новая редакция её артефактов.

Нормативная граница задачи — доставка presentation-ресурсов для последующих
экранов. Она не определяет новые правила получения, состава или развития
симбионта и не публикует `CHR-018`.

## Решение

### 1. Каталог источника и исторический манифест

Общим местом для таких поставок является `artifacts/symbiont-media/`. Исходные
XLSX остаются read-only и покрываются общим `artifacts/CHECKSUMS.sha256`.

`Symbiosis_V7_Delivery_Manifest_v1.2.xlsx` остаётся неизменным историческим
манифестом исходной 12-file baseline. Две mapping-книги — отдельная additive
delivery, поэтому их появление не разрешает задним числом переписать состав или
печать исходной поставки. Суммы всех фактически поставленных файлов ведёт общий
checksum-манифест; сам historical Delivery Manifest не редактируется.

### 2. Точный join по SpeciesKey

Единственный ключ соответствия — `SpeciesKey` из
`generated/spec/character/symbionts.json`. Играбельное множество состоит ровно из
23 записей со `Status="ACTIVE"` и `SymbiontKind="ORDINARY"` либо
`"SYMBIOTIC_MONSTER"`: 20 обычных видов и 3 симбиотических чудовища. Остальные
51 записи реестра — legend/link records, а не дополнительные играбельные виды.

Каждая книга независимо сопоставляется с этим множеством. Якорь OOXML связывает
изображение со строкой, строка даёт `SpeciesKey`; порядок `xl/media/imageN.png`,
порядок загрузки и совпадение позиции строки ключом не являются. Порядок записей
в manifest сохраняет только порядок исходного `symbionts.json`.

### 3. Два каталога и один generated manifest

Importer записывает PNG под именем `${SpeciesKey}.png` в два раздельных каталога:

```text
generated/media/symbionts/
generated/media/development-trees/
```

`generated/spec/symbiont-media/manifest.json` содержит пути двух исходных книг,
оба каталога и упорядоченные записи:

```text
species[{speciesKey,artFile,developmentTreeFile}]
```

В git попадает только manifest, пересобираемый `tools/import`. Каталоги media
остаются вне git по ADR 0016. До записи обе книги проходят полную проверку;
заменяются только два собственных выходных каталога importer'а.

Manifest является object-shaped lookup index, а не array-row таблицей. Он явно
зарегистрирован среди пропускаемых индексов seed: существующие 114 array tables,
20 287 строк и 9 metadata passports не раздуваются второй сериализацией
manifest.

### 4. Полнота и исходные PNG-байты

Для каждой книги обязательны ровно 23 строки, 23 anchors и 23 embedded media
parts. Импорт отклоняет пропавший, лишний, неизвестный или повторный
`SpeciesKey`, повторное имя файла или anchor, неверную строку, небезопасный
basename, расширение не `.png`, неверную PNG-сигнатуру и нессылаемую media part.
Ошибка происходит до записи и называет нарушенное соответствие.

В output переносятся именно PNG-байты, извлечённые из поставленной книги по
якорю. Importer не масштабирует, не перекодирует и не подбирает изображение по
содержимому. Тесты сравнивают все 46 output-файлов с source bytes и требуют
повторного детерминированного импорта.

### 5. Изображение — представление, не механика

**Изображение дерева — представление, не источник механики.** Оно не является
вторым источником структуры дерева. Расхождение изображения с
`development-nodes.json` не делает изображение правильным.

Ни одно правило, число, `NodeRef`, связь или порядок развития из картинки не
вычитываются. `development-nodes.json`, `symbionts.json` и существующие доменные
контракты этой поставкой не меняются.

### 6. Граница поставки

Этот ADR не вводит runtime/publication contract, outer protocol или проекции.
`CHR-018`, обязательный B-roll #147, ручной composition #145 и equipment #146
остаются отдельными задачами с собственными критериями приёмки. Наличие PNG не
объявляет эти сценарии или весь V1 готовыми.

## Обоснование

Явный `SpeciesKey` уже связывает обе mapping-книги с реестром видов. OOXML anchor
сохраняет это соответствие независимо от лексикографических имён и порядка
вложений. Проверка полного множества исключает частичную поставку, которую UI
мог бы принять за полную.

Раздельные каталоги позволяют использовать устойчивое имя `${SpeciesKey}.png`
без префиксов типа изображения и не смешивают две разные presentation-роли.
Перенос исходных байтов устраняет необязательный конвертер и делает
воспроизводимость проверяемой без новых зависимостей.

Сохранение historical manifest отделяет факт исходной поставки v1.2 от
последующего пополнения. Общий checksum-манифест фиксирует новые файлы без
изменения исторического документа.

## Отвергнутые альтернативы

| Вариант                                                                      | Причина отказа                                                                                           |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Сопоставление по имени файла, порядку строк или `imageN.png`                 | Имя вложения и upload order не являются ключом вида; совпадение порядков не доказывает соответствие      |
| Один смешанный каталог для арта и деревьев                                   | Стирает различие presentation-ролей и требует искусственных префиксов при одинаковом `${SpeciesKey}.png` |
| Конвертация или повторное уменьшение PNG в importer'е                        | Добавляет зависимость и необратимое преобразование без необходимости; поставленные bytes уже пригодны    |
| Чтение узлов, чисел или связей с изображения дерева                          | Создаёт второй, непроверяемый источник механики вместо `development-nodes.json`                          |
| Обновление sealed Delivery Manifest v1.2                                     | Молча переписывает историческую 12-file baseline вместо оформления отдельной additive delivery           |
| Коммит generated PNG                                                         | Повторно хранит большие бинарные output, восстанавливаемые importer'ом; противоречит ADR 0016            |
| Публикация `CHR-018`, новые проекции или runtime #147/#145/#146 в этом срезе | Смешивает поставку ресурсов с независимыми игровыми сценариями и расширяет scope #139                    |

## Последствия

- `npm run import` восстанавливает 23 арта, 23 изображения деревьев и один
  manifest из двух поставленных XLSX без ручных шагов и новых зависимостей.
- Любое неполное или неоднозначное соответствие останавливает импорт; частичный
  набор не считается допустимым результатом.
- После клона по-прежнему обязателен `npm run import`: PNG не хранятся в git.
- Последующие UI-задачи получают стабильные presentation paths, но обязаны
  самостоятельно реализовать и проверить свои runtime-контракты.
- Изменение правил или структуры развития требует отдельного источника и ADR;
  изображения таким источником не становятся.
