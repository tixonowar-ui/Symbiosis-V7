# ADR 0009 — Очередь бросков привязана к команде

- **Статус:** принято
- **Дата:** 2026-08-01 (перенесено в ADR 2026-08-07)
- **Источник:** Cross-Registry Audit Report v1.2 — AUD-016

## Контекст

Аудит обнаружил неавторизованный пул предварительных бросков (AUD-016):
результат броска мог быть использован не той командой, для которой был
запрошен.

## Решение

Очередь бросков ведётся **по `rollRequestId` на каждую команду**.

Нормативное основание: roll contract. Результат проверки — переиспользования
между командами нет.

## Обоснование

Решение перенесено из аудита без изменений.

Заранее набранный пул бросков позволяет выбрать удобный результат постфактум.
Привязка к `rollRequestId` конкретной команды это исключает: бросок,
запрошенный для одной команды, не может быть предъявлен для другой.

## Последствия

- `rollRequestId` выдаётся хостом при запросе броска и принадлежит **одной**
  команде.
- Пул бросков «про запас» не формируется. Результат без соответствующего
  `rollRequestId` отклоняется fail-closed.
- Entity lifecycle `rollRequest` (`src/domain/entities/roll-request`) реализует
  этот контракт; переход, не описанный в цикле, — ошибка.
- Тест обязан покрывать негативный случай: результат броска, предъявленный для
  чужой команды, **отклоняется**.
