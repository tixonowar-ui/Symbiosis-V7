# ADR 0002 — Технологический стек

- **Статус:** принято
- **Дата:** 2026-08-06

## Контекст

Нужен стек для offline-first LAN-приложения с единственным авторитетным хостом,
разворачиваемого на Windows 10/11 x64 ([ADR 0001](0001-target-platforms.md)).
Ключевые ограничения: работа без интернета, установка без цепочки сборки на
машине пользователя, один процесс-владелец состояния.

## Решение

| Слой            | Выбор                   | Версия на момент решения |
| --------------- | ----------------------- | ------------------------ |
| Рантайм         | Node.js LTS             | 24.19.0 «Krypton»        |
| Язык            | TypeScript, strict      | 6.0.3                    |
| Хранилище       | better-sqlite3          | 13.0.3                   |
| HTTP            | Fastify                 | 5.11.2                   |
| Канал состояния | ws + @fastify/websocket | 8.21.2 / 11.3.0          |
| UI              | React + Vite            | 19.2.8 / 8.2.1           |
| Тесты           | vitest + Playwright     | 4.1.10 / 1.62.1          |

Версии зафиксированы точно (`--save-exact`) и закреплены `package-lock.json`.

## Обоснование

### Node 24 LTS

Проверено на целевой машине: `process.release.lts` возвращает `Krypton`, то
есть это действительно LTS-линия, а не Current. ABI 137, x64. Диапазон
зафиксирован как `>=24.19.0 <25`, чтобы смена мажора была осознанным решением.

### better-sqlite3 и отсутствие цепочки сборки

Это единственная нативная зависимость, и она была главным риском: компиляция из
исходников на машине пользователя потребовала бы Visual Studio Build Tools и
Python, что противоречит offline-first поставке.

Проверено фактически: начиная с версии 13 пакет кладёт готовые бинарники прямо
в npm-тарбол — `prebuilds/win32-x64.node` среди восьми платформ. Это Node-API,
то есть бинарник не привязан к ABI конкретной версии Node. После установки:

- каталог `node_modules/better-sqlite3/build/` отсутствует — компиляции не было;
- `require('better-sqlite3')` открывает БД и выполняет запрос;
- SQLite 3.53.4.

Важная деталь: в пакете есть `binding.gyp`, и npm по умолчанию запускает для
таких пакетов `node-gyp rebuild`, если у них нет собственного install-скрипта.
npm 11 не выполняет неодобренные install-скрипты, поэтому сборка не
запускается и используется готовый бинарник. Именно поэтому `engines.npm`
объявлен как `>=11`: на более старом npm установка попыталась бы
компилировать и потребовала бы компилятор.

Синхронный API better-sqlite3 выбран сознательно. Хост — единственный
процесс-писатель, состояние авторитетно и живёт в памяти одного процесса;
асинхронная обёртка добавила бы точки переупорядочивания там, где нужна
атомарность.

### Fastify + ws

Fastify отдаёт статику рендерера и HTTP, `ws` держит канал состояния с
подписками по ролям. Разделение намеренное: HTTP для загрузки и разовых
запросов, WebSocket для потока ревизий состояния.

### React + Vite

Рендерер generic — он строит формы по атласу, а не по коду на экран. React
покрывает это без сюрпризов, Vite даёт быстрый цикл разработки и
self-contained бандл без внешних загрузок в рантайме.

## Альтернативы

- **Electron** — отвергнут: увеличивает поставку на порядок и не нужен, раз UI
  и так открывается в браузере по LAN.
- **node:sqlite** (встроенный в Node) — отвергнут: убирает нативную
  зависимость, но на момент решения API уже, и привязка схемы к версии
  рантайма нежелательна при фиксированном LTS.
- **Express** — отвергнут в пользу Fastify: строгая схема и валидация ближе к
  fail-closed-подходу проекта.

## Последствия

- Установка на целевой машине не требует компилятора, Python и интернета сверх
  самого `npm install`.
- Обновление better-sqlite3 обязано перепроверяться на наличие
  `prebuilds/win32-x64.node`: если пакет вернётся к сборке из исходников, это
  ломает поставку и требует пересмотра решения.
- `npm ci` на npm старше 11 может повести себя иначе — диапазон в `engines`
  это фиксирует.
