# ADR 0003 — Порядок источников правды

- **Статус:** принято
- **Дата:** 2026-08-06

## Контекст

Проект строится от поставленных артефактов, а не от кода. Артефактов много —
12 файлов в `artifacts/` — и они частично перекрываются: одно и то же решение
может быть упомянуто в реестре правил, в атласе, в Q&A и в отчёте аудита.
Нужен однозначный порядок разрешения противоречий.

Осложняющее обстоятельство: атлас v1.2 объявляет собственный порядок
приоритетов, и в нём **старшие предметные реестры стоят выше самого атласа** —
атлас позиционирует себя как спецификацию реализации (уровень 4), а реестры
как источник механик (уровень 3).

## Решение

Порядок двухуровневый: документы проекта выше всех артефактов, внутри
артефактов действует порядок, объявленный атласом.

1. `docs/adr/` — решения проекта
2. `docs/` — прочая проектная документация
3. `artifacts/registries/Symbiosis_V7_Delivery_Manifest_v1.2.xlsx` — состав
   поставки, совместимость, границы замороженных артефактов
4. Старшие предметные реестры: Executable Rules, Character/Skills/Symbionts,
   Items, Effects/Diseases, Canonical Bestiary, Default Sentient Enemy
5. Спецификации реализации: Soundtrack Registry (звук),
   `artifacts/atlas/` Web UI Screen Atlas v1.2 (UI)
6. All Questions and Answers Registry — только если решение ещё не
   материализовано в старшем реестре
7. `artifacts/packs/` Runtime Pack — только точные системные шаблоны и арт,
   никогда не источник новых правил
8. Cross-Registry Audit Report — свидетельство консистентности, не
   самостоятельный источник механик

## Обоснование

Артефакты — снимок на момент поставки. Решения, принятые в ходе разработки,
новее и учитывают то, чего авторы артефактов не знали, поэтому `docs/adr/`
стоит выше. Это не разрешение переписывать механику: ADR, меняющий игровое
правило, обязан ссылаться на артефакт, который он уточняет, и объяснять
расхождение.

Внутри артефактов сохранён порядок самого атласа, а не переизобретён. Атлас
описывает, **как показать** механику; реестр описывает, **какая она**. Если
экран показывает не то, что считает правило, — прав реестр, а атлас требует
исправления.

## Известное расхождение: атлас против манифеста

`Delivery_Manifest_v1.2` перечисляет как UI-контракт файл
`Symbiosis_V7_Windows_UI_Screen_Atlas_v1.1.pdf` (57 МБ, 279 страниц). Этого
файла в поставке нет. Вместо него поставлен
`Symbiosis_V7_Web_UI_Screen_Atlas_v1.2` в двух машиночитаемых форматах — JSON
и Markdown.

Расхождение разрешается самим атласом v1.2, который прямо заявляет:

> Старый PDF не нужен для реализации; его страницы приведены только для
> трассировки.

То есть атлас v1.2 вышел позже манифеста v1.2 и заменяет PDF. Манифест
остаётся авторитетным по остальным 10 артефактам — их SHA-256 проверены
побайтово и совпадают.

Действующим UI-контрактом считается **Web UI Screen Atlas v1.2**:
`graphDigest` `693910e4…`, `contentDigest` `ceace6ea…`, 0 открытых
UX-вопросов.

## Последствия

- `npm run checksums:verify` покрывает 13 файлов: 11 из манифеста (без
  отсутствующего PDF) плюс два файла атласа v1.2.
- Появление PDF-атласа в поставке не отменяет это решение: он остаётся
  средством трассировки.
- Ссылка на источник обязательна там, где значение неочевидно. «Взято из
  реестра» без указания какого — не ссылка.
