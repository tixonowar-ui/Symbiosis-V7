# ADR 0075 — Безопасные настройки и следующий запуск listener

- **Статус:** принято владельцем, issue #208
- **Дата:** 2026-11-02
- **Дополняет:** ADR 0018, 0021, 0064, 0068, 0071, 0073–0074
- **Граница:** контракт Atlas; прикладная реализация — #174

## Принятое решение

Владелец принял предложение #208 целиком: «Принять целиком, сеть применять
при следующем запуске». Это разрешает соответствующее обновление Atlas JSON
и Markdown и новый ADR. Каждая новая возможность получает реальные элементы
управления в приложении. Команда без экранного ввода и результата не завершает
приёмку #208 или #174.

Atlas 1.9 сохраняет schemaVersion 1.2.0, legacy filenames v1.2, 376 форм
и прежние игровые реестры. Состав этой поправки: 1700 переходов, 112 workflow,
2449 QA, 1264 CTA. Исходный фактический состав Atlas 1.8 — 1698 переходов
и 1262 CTA; расхождение прежнего текстового счётчика ADR 0073 зарегистрировано
отдельно в #210. Принятый ADR 0073 и байты прежней поставки не исправляются
задним числом.

## CMP-008

Новая `UI-CMD-CAMPAIGN-SETTINGS-SET` принимает commandId, campaignId,
expectedSettingsRevision, title, descriptionOrNull, defaultFutureRollMode
(`MANUAL|AUTO`) и network с hostAddress, hostPort, networkInterface.
Идентичность GM определяет существующая аутентифицированная authority.
Поля metadata и режим проверяются по контракту создания кампании; новые
длины, defaults или игровые ограничения не вводятся.

Форма содержит ввод названия, описания и режима, ввод сети следующего запуска,
«Сохранить настройки» и «Отменить изменения», ошибки полей и подтверждённую
ревизию. Отмена удаляет только несохранённый ввод и возвращает в существующую
CMP-007. Арт показан по прежнему checksum либо явно отсутствует, без file picker.
Capacity и пароль сохраняются отдельными командами CMP-014/CMP-015.

Metadata обновляет текущие настройки и отображение. Новый режим бросков
относится только к новым requests. Ни одна команда не переписывает прежний
mode snapshot, результат броска, admission sheet, birth, receipt или FINAL.

Любое сохранение настроек требует safe boundary и отсутствия pending operation.
Сохранение атомарно создаёт settings revision, checkpoint и receipt.
Exact replay возвращает исходную квитанцию отдельно от текущей проекции.
Stale revision, изменённый повтор, чужая authority, невалидный ввод и
конфликтующая операция приводят к отказу без записи.

## Сеть и восстановление

Изменить hostAddress, hostPort или networkInterface можно только в PAUSED,
на safe boundary без pending operation. Сохраняется конфигурация **следующего
запуска listener**. Текущий listener и его соединения эта команда не меняет.
CMP-008 отдельно показывает действующий endpoint или отсутствие listener
и сохранённый следующий endpoint. CMP-006 и QR описывают только фактически
работающий listener; возврат на эту форму не применяет новую конфигурацию.

Следующий запуск проверяет и связывает сохранённый адрес. Занятый порт,
недоступный адрес или интерфейс дают явный отказ без fallback и без нового
campaignId или GM context. Host identity, character/controller bindings
и привязки восстановления сохраняются.

NET-009 разрешает явный ввод адреса/порта для ручного reconnect существующего
campaign peer. Используется прежняя закреплённая host identity: другой ключ
отклоняется до принятия snapshot. Это не OPEN, новая TOFU, admission или
создание copy. Неуспешное подключение не заменяет последний аутентифицированный
endpoint и не теряет commandId для reconciliation.

Дополнительные поля NET-009 заключены в
`pinnedCampaignPeerReconnectOrNull`. Для локального GM или прежнего recovery
без campaign-peer binding используется null и существующий маршрут.
Несуществующий peer pin для них не создаётся.

## Совместимость и границы

Существующие CMP-007/GM-001/GRP-001 и CMP-008 используют одну authority,
включая PAUSED после Start. Навигация и Resume не обходят первый Start,
не создают вторую сцену или административную оболочку. Совместный вход #187
сохраняется; NPC, group/map mutations и прочие будущие возможности не открываются.
Пароли, verifiers, настройки и сведения чужих устройств не входят в player payload.

Новая поставка должна иметь точный sealed baseline по ADR 0071: сохраняются
исторические B0/B1/B2/B3, добавляются только явные forward-пары к B4 и
тождественное чтение. Сравниваются точные наборы путей и SHA-256, меняются
только два Atlas-файла; остальные 20 артефактов, Runtime Pack и replay catalog
digests остаются прежними. Совместимость не выводится из номера версии.
Saved snapshots и receipts не мигрируют переписыванием содержимого.

JSON, Markdown, workflow/CTA/transitions, journeys, requirements и QA mirrors
согласуются вместе. Проверки literals и полных объектов сохраняют отказ при
любом неутверждённом дрейфе. Generated создаётся только импортом.
