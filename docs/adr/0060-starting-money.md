# ADR 0060 — Стартовые деньги CHR-038

- **Статус:** принято
- **Дата:** 2026-10-29
- **Реализует:** issue #153
- **Дополняет:** [ADR 0021](0021-roll-model.md),
  [ADR 0025](0025-character-draft-checkpoint-scope.md),
  [ADR 0059](0059-weapon-profiles-and-pure-entry.md)

## Контекст

После #152 профиль оружия неизменяем, а следующий `CHR-038` подписан хостом.
Нужен отдельный D20 рекомендации достатка с восстановлением без переброса.
Источники: Item Registry v1.6, `rule-trace` — `CORE-172/Q-CORE-052`,
`AQ2-003/004`; `catalogue` — `RES-CUR-000`; `dictionaries` —
`NEVER_PROGRESSION`; Atlas `CHR-038`, `J-CHAR-CREATE/STARTING_ITEMS`,
workflow `UI-CMD-CHAR-CREATION-ROLL-COMMIT` и `UI-CMD-CHAR-WIZARD-CHECKPOINT`.

В `CORE-172` ранняя неопределённость отображения качества на деньги явно
заменена авторской дельтой Q-CORE-052. Эта дельта задаёт шкалу полностью,
но не задаёт суммы. `AQ2-004` оставляет итоговые деньги мастеру.

## Решение

### 1. Отдельная рекомендация достатка

| D20   | Рекомендация из CORE-172 |
| ----- | ------------------------ |
| 1–4   | нет денег                |
| 5–9   | малая сумма              |
| 10–14 | обычная                  |
| 15–18 | крупная                  |
| 19    | исключительная           |
| 20    | редкое состояние         |

Шкала денег не подменяется словарём качества предметов. Чистый domain
принимает грань 1..20 и возвращает `kind`, `label`, `range`, `rawFace`.
Технический `kind` адресует одну строку шкалы и не является суммой.
Каталог сверяет полные нормативные алгоритмы и границы с поставленными
строками; неизвестные или изменённые источники отклоняются.

`gmFinalizationRequired=true` остаётся обязательным ограничением. Даже
«нет денег» не назначает финальную сумму 0. Приложение не меняет валюту,
количество имущества, характеристики, XP или счётчики и не выполняет master
approval. Natural 1/20 не запускают критическую цепочку создания.

### 2. Связь с профилем и совместимость истории

Optional `startingMoneyStage` входит в whole-checkpoint, связывает
weapon checkpoint receipt и завершённый profile receipt. Новый успешный
submit/acknowledge профиля атомарно сохраняет один `moneyRollRequestId`,
snapshot режима ввода и pending money stage. Entry использует существующий
profile request/receipt, который история не считает дважды.

Это техническая связь продолжения внутри atomicity профиля: она не выполняет
денежный бросок и не создаёт рекомендацию или результат следующей игровой
операции. INVALID профиля не создаёт money stage и не выделяет money ID.

Старый завершённый профиль без нового optional ID остаётся неизменным.
Его адрес запроса вычисляется детерминированно: префикс `starting-money:` и
SHA-256 UTF-8 JSON-массива `["symbiosis.starting-money.v1", characterDraftId,
profileReceiptId]`. Это техническая идентичность, не seed или случайное
значение. Чтение создаёт только представление pending запроса; в SQLite
ничего не записывается, allocator и sampler не вызываются.

Первый `CHR-038` roll атомарно материализует такую стадию вместе с результатом.
Повторный `CHR-023 SUBMIT` или `CHR-024 ACKNOWLEDGE` для миграции запрещён.
Исторический receipt не переписывается. Отсутствующее optional поле отличается
от `null`, пустой строки и некорректного ID: последние отклоняются. Derived
адрес проверяется на коллизии с существующими durable IDs до RNG.
Loader сверяет виртуальный адрес с уже занятыми IDs, но не добавляет его
в набор durable IDs до материализации. Preflight первого roll повторяет эту
проверку и отдельно исключает совпадение с новым command ID и receipt ID.
После записи адрес занимает общий namespace; заимствованные entry IDs
профиля повторно не резервируются.

### 3. Roll, checkpoint и восстановление

`STARTING_MONEY_ROLL` принимает один addressed request. AUTO вызывает host
sampler ровно один раз внутри транзакции после guards; MANUAL требует одну
явную грань и не вызывает sampler. Режим наследуется из создания персонажа
и остаётся immutable. После первого committed display request, грань и receipt
не заменяются. AUTO receipt входит в существующий `randomReceiptIds`;
свидетельства формул оружия по-прежнему не являются физическими бросками.

`STARTING_MONEY_CHECKPOINT` проверяет сохранённый money receipt, сохраняет
рекомендацию и обязательность финализации мастером. Следующая форма
`CHR-037` подписывается, но не публикуется; `CHR-038/CHECKPOINTED` actionless.

Replay возвращает прежний receipt; changed payload, stale revisions, чужие
request/checkpoint IDs и коллизии отклоняются. Loader заново проверяет
привязку entry, режим, physical roll, рекомендацию, порядок и ревизии истории.
Post-write validation остаётся внутри транзакции. Refresh/reconnect/restart
и SQLite reopen не выделяют новый ID и не вызывают RNG. SQL-схема и outer
protocol не меняются.

### 4. Safe-return и presentation authority

Atlas `CHR-038::CTA::002` возвращает именно на `CHR-022`, сохраняя weapon,
profile и money receipts. Возобновление проходит через ранее подписанную
ветвь `CHR-023` либо `CHR-024` и возвращает тот же `CHR-038` без нового
submit/acknowledge профиля. Эти переходы меняют только presentation revision.
После money checkpoint доступен только actionless `CHR-038`.

У старого завершённого профиля сохранённая presentation `CHR-023/024` с той
же ревизией, что final profile receipt, трактуется как начальное продолжение
на `CHR-038`. Более поздняя signed presentation сохраняет явно выполненный
safe-return, поэтому restart не перескакивает назад к деньгам. Клиентский URL
или история браузера authority не создают.

Player projection содержит только рекомендации и необходимые адреса,
показывает `gmFinalizationRequired=true` и не передаёт raw Rule IDs,
источники, availability trace или скрытые мастерские данные.

## Обоснование

Все шесть диапазонов заданы старшим предметным реестром. Отсутствие числовой
суммы является границей задачи, а не основанием угадывать её. Отдельная запись
денежного D20 сохраняет независимость восьми имущественных операций AQ2-003.
Детерминированный legacy адрес позволяет продолжить старый receipt без
повторной необратимой команды профиля и без mutation при чтении.

## Последствия

Публикуется `CHR-038`, а `CHR-037` остаётся следующим срезом #154. Согласование
мастером, итоговые деньги, пять произвольных позиций, общий inventory runtime
и final save не реализуются. Новые и исторические pending стадии имеют разный
entry mode; обе проверяются по одному источнику и восстанавливаются без RNG.
