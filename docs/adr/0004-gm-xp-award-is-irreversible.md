# ADR 0004 — Начисление опыта мастером необратимо

- **Статус:** принято
- **Дата:** 2026-08-01 (перенесено в ADR 2026-08-07)
- **Источник:** Cross-Registry Audit Report v1.2 — AUD-002, AUD-003, CHG-001,
  CHG-002, RTC-001…RTC-004, Q-GM-XP-001

## Контекст

Произвольное начисление опыта мастером не было определено в реестрах
(AUD-002), и отдельно был не определён откат такого начисления (AUD-003).
Вопрос `Q-GM-XP-001` — «Можно ли откатить начисление?» — закрыт прямым ответом
автора от 2026-08-01.

## Решение

Мастер может начислить опыт напрямую. **Закоммиченное начисление всегда
валидно и не отменяется.** Обратных операций не существует.

Правило `CORE-234` — immutable GM grant. Источник начисления `GM_DIRECT`
добавлен в `CORE-007`.

Машинные инварианты (RTC-001…RTC-004):

| Контракт | Вход                                       | Предусловие                                           | Переход                               | Запрещено                                   |
| -------- | ------------------------------------------ | ----------------------------------------------------- | ------------------------------------- | ------------------------------------------- |
| RTC-001  | `awardId, actor, symbiont, baseXP, reason` | `PLAYER_CHARACTER`; owned `xpEligible`; `baseXP >= 1` | `xp += base × raceMultiplier`         | rollback / delete / negative / compensation |
| RTC-002  | повтор `awardId`                           | тот же payload                                        | вернуть **тот же** receipt            | второе изменение                            |
| RTC-003  | раса `FREE`                                | валидное начисление                                   | множитель `2` ровно один раз          | множитель счётчиков                         |
| RTC-004  | текущие счётчики                           | любые значения                                        | не читать и не писать; никакого `3:1` | расход счётчиков                            |

## Обоснование

Решение перенесено из аудита без изменений. Обоснование принадлежит автору
артефакта, а не этому ADR.

Практическое следствие для реализации: отсутствие отката — не пробел, который
надо закрыть, а сам контракт. Операция, «исправляющая» ошибочное начисление
отрицательной дельтой, нарушает RTC-001.

## Последствия

- В реестре handler'ов **нет** операций отката, удаления, отрицательного
  начисления и компенсации опыта. Попытка такой операции отклоняется
  fail-closed.
- `awardId` идемпотентен: повторный запрос с тем же payload возвращает прежний
  receipt и **не** создаёт второе изменение.
- Множитель расы `FREE` применяется ровно один раз за начисление — двойное
  применение это баг.
- Счётчики опыта при прямом начислении мастера не участвуют: ни чтения, ни
  записи, ни конверсии `3:1`.
- Негативные тесты обязаны покрывать каждый запрет из таблицы: тест должен
  доказывать, что операция **отсутствует**, а не что она «пока не реализована».
