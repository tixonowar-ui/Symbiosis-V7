# ADR 0078 — Источник начального времени NPC и первого импорта

- **Статус:** принято владельцем, решения 1–2 issue #221
- **Дата:** 2026-11-05
- **Дополняет:** ADR 0068, 0071, 0073, 0075 и 0077
- **Граница:** поставка Atlas и точная совместимость; runtime — #187/#212

## Контекст

До длительного выполнения оставшейся очереди владелец поручил проверить
продуктовые блокеры. Независимое чтение источников выявило три незамкнутых
сценария. NPC-016 разрешает календарные состояния с обязательным `startsAt`,
но начальное время можно менять до Start. GM-002 — единственный источник
подписанного импорта — требует уже выбранного персонажа. Смена мастера
требуется Q-CAMP-009, однако guards восстановления требуют прежнего current GM,
а выбор преемника, его принятие роли и доверие новой host identity не замкнуты.

Владелец явно принял пять предложений 2026-11-05. Эта поставка материализует
первые два в Atlas JSON/Markdown и проверках источника. Штатная передача
мастера и аварийное recovery поставляются отдельно в той же #221: обычный
лимит 2000 строк artifacts не покрывает весь bundle. Каждая поставка имеет
собственные review, полный gate, CI и squash; #221 закрывается после всех
частей. Эта первая поставка не завершает зависимые
runtime-задачи и не вводит второй CMP-007/GM-001 context.

## Решение

### Календарные состояния NPC

До первого Start успешное сохранение NPC с эффектом или таймером, привязанным к мировой
календарной шкале, требует подтверждённого начального времени, заданного GM командой
`UI-CMD-CAMPAIGN-INITIAL-TIME-SET`. Defaults, `Date.now`, timezone и фиктивная
сцена не используются. Из wizard доступен реальный control перехода к вводу
времени и безопасный возврат в ту же host-bound попытку. После Start применяется текущий campaign clock: новое начальное время и lobby revision для этой ветви не требуются.
В дочернем контексте NPC новый Start недоступен; после безопасного выхода
обычный lobby-контекст сохраняет прежние возможности. Исторический exact replay
квитанции Start не меняется.

Первый такой save до Start атомарно сохраняет версию, receipt и привязку
к подтверждённой начальной минуте. После него изменение этой минуты до Start
отклоняется с объяснением. Удаление эффекта из следующей версии не удаляет
исторический anchor и не снимает фиксацию. NPC без календарных состояний
фиксацию не создаёт. OPEN, просмотр и отмена не считаются save.

Старые версии, timestamps и квитанции неизменны. Повтор точного запроса
возвращает прежний receipt, изменённый/stale/foreign запрос не пишет ничего.
Ни автоматические часы, ни ADVANCE_TIME, placement, map marker или combat
actor этой поставкой не добавляются.

### Первый импорт без выбранного PC

GM-002 получает явный вариант `EMPTY_NO_CHARACTER` и вход из текущего GM-001
при отсутствии выбранного `campaignCharacterId`, включая ноль допущенных PC.
Вариант показывает импорт и безопасный возврат. Поля выбранного персонажа,
HP, группы, маркера и места явно отсутствуют, а не заполнены фиктивными
значениями. Контракт обычного selected-character варианта сохраняется.

Импорт использует прежний signed origin и текущую GM authority. Он не создаёт
автоматический admission, controller или сцену. Guard HANDOFF-ACK согласуется
с уже принятой ветвью `IMPORTED_OWNER_CLAIM` до admission; обычные условия
передачи управления допущенным персонажем не ослабляются.

## Обоснование

Фиксация первой календарной привязки сохраняет смысл уже записанных абсолютных
timestamps без выдуманной процедуры пересчёта. Пустой вариант GM-002 устраняет
циклическое требование иметь персонажа перед первым импортом. Контракт
HANDOFF-ACK согласован с уже принятой ветвью imported owner claim.

## Последствия и совместимость

Поставляется Atlas 1.11/B6 с прежними schemaVersion и legacy filenames.
Меняются только два файла Atlas и их CHECKSUMS; остальные 23 artifact paths,
включая игровые реестры, Runtime Pack и весь арт, побайтно сохраняются.
Состав: **376 форм, 1708 переходов, 112 workflow, 2449 QA и 1272 CTA**.
Два новых CTA дают child-переход к существующему времени и bound возврат;
новых форм или workflow-команд нет. Seed сохраняет 115 array tables и 10 metadata;
два новых перехода увеличивают точный inventory с 20 336 до 20 338 строк.
Semantic graphDigest/contentDigest
сохраняются по ADR 0037/0049.

в workflow/CTA/transitions/journeys/requirements/QA и независимом Markdown.

tests продолжают ловить обход guards. Generated производится только импортом.
Runtime получает эти возможности отдельными задачами с реальными controls,
независимым ревью, полным чистым прогоном и CI точного SHA.
