# ADR 0019 — `generated/seed` пересобирается, а не хранится в git

- **Статус:** принято
- **Дата:** 2026-08-09
- **Заменяет:** строку про `generated/seed` в
  [ADR 0016](0016-what-generated-is-committed.md). Остальные решения ADR 0016 —
  про `spec`, `types` и `media` — остаются в силе
- **Источник величин:** пробная сборка seed по задаче #6, 2026-08-09

## Контекст

[ADR 0016](0016-what-generated-is-committed.md) отнёс `generated/seed` к
хранимому в git. Решение принималось 2026-08-08, когда каталог был пуст: в
таблице величин того же ADR напротив него стоит «пусто, веха M2». То есть
решали про пустоту, а не про файл.

Теперь файл измерен. Пробная сборка по требуемой схеме — 112 таблиц массивов,
20 535 строк и отдельная таблица для восьми `meta.json` — дала:

| Величина                    | Значение                                                           |
| --------------------------- | ------------------------------------------------------------------ |
| Размер                      | 30 314 496 байт (30,31 МБ, 28,91 МиБ)                              |
| SHA-256, два прогона подряд | `27c448c41b82dc94f7b15cafe4237261c2d8c7afecddd23a1a20fdf36447ebc2` |
| SQLite                      | 3.53.4, в заголовке файла `3053004`                                |
| Побочные файлы              | `-wal`, `-shm`, `-journal` не создаются                            |

Задача #6 несла обязательное стоп-условие: измерить размер и остановиться, если
он превышает 25 МБ, не принимая решение о хранении в рамках реализации. Условие
сработало, код не писался.

### Ещё одно: репозиторий уже противоречил сам себе

`.gitignore` содержит `*.sqlite` в разделе локальных баз. Под это правило
`generated/seed/seed.sqlite` попадает целиком. То есть строка ADR 0016 «seed —
в git» и соседний комментарий в самом `.gitignore` расходились с фактическим
поведением git: коммит потребовал бы отдельного исключения, которого никто не
писал. Это решение заодно снимает расхождение.

## Решение

**`generated/seed` не хранится в git и пересобирается `npm run import`** —
на тех же основаниях, что `generated/media`.

`generated/seed/.gitkeep` остаётся, чтобы каталог существовал после клона.

## Обоснование

ADR 0016 применял к каждому каталогу четыре критерия. Seed проверен по ним же:

| Критерий                                        | `spec` / `types`               | `media` | `seed.sqlite`                                   |
| ----------------------------------------------- | ------------------------------ | ------- | ----------------------------------------------- |
| Диффится, показывает изменение поставки в ревью | да, главный инструмент ревью   | нет     | **нет** — двоичный файл на 30 МБ                |
| Нужен, чтобы репозиторий собирался без импорта  | да, `types` входит в typecheck | нет     | **нет** — на него ничто не ссылается            |
| Побайтово восстанавливается импортом            | —                              | да      | **да** — два прогона дали один SHA-256          |
| Производен от уже покрытого контрольной суммой  | —                              | да      | **да** — из `spec`, тот из `artifacts/` под SHA |

Совпадение с профилем `media` полное, оснований коммитить — ни одного.

Цена исключения близка к нулю: `npm run import` после клона **уже обязателен**
из-за `media`, и это записано в `AGENTS.md`, раздел 2. Нового шага в рабочем
процессе не появляется.

Цена коммита постоянна и необратима без переписывания истории: 30 МБ в историю
при каждой пересборке, причём чаще не от новой поставки артефактов, а от правок
самого генератора — любая смена формы таблиц переписывает файл целиком.
Взамен не даётся ничего: двоичный файл в PR показывает только факт изменения.

Отвергнутые альтернативы:

| Вариант                      | Почему отклонён                                                                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Коммитить как есть           | +30 МБ в историю на каждую пересборку без выигрыша в проверяемости. Ровно то основание, по которому ADR 0016 исключил `media`                                      |
| Git LFS                      | ADR 0016 отверг его до ~200 МБ в `artifacts/`; сейчас там 66,7 МБ, порог не достигнут. Добавляет обязательный шаг установки, что противоречит offline-first сборке |
| Отложить seed до потребителя | Оставляет веху M1 открытой на неопределённый срок. Генерация дёшева и проверяет отображение `spec` в реляционную форму сквозным прогоном                           |
| Хранить сжатым               | Сжатый двоичный файл диффится не лучше и по-прежнему переписывается целиком; проблема не в объёме одной копии, а в числе копий в истории                           |

## Последствия

- Первый `git clone` остаётся около 95 МБ и не растёт на 30 МБ за поставку.
- После клона `npm run import` обязателен и для seed — как и для `media`.
  Тесты seed читают то, что произвёл импорт, и запускаются после него.
- CI шаг «Pipeline output is reproducible» на seed не реагирует: файл
  игнорируется git, поэтому в чистоте рабочего дерева не участвует.
  Детерминизм seed проверяется собственным тестом, а не диффом.
- Побайтовая воспроизводимость становится обязательной, а не желательной: она
  единственная гарантия, что пересобранный seed совпадает с тем, на котором
  задача проверялась. Гарантия действует **при закреплённой библиотеке**:
  заголовок SQLite хранит `SQLITE_VERSION_NUMBER`, поэтому обновление
  `better-sqlite3` законно меняет байты файла. Тест обязан сверять версию и
  падать с внятным сообщением, а не оставлять необъяснённое расхождение хеша.
- `.gitignore` перестаёт противоречить документации.
- Правило ADR 0016 «`generated/spec` и `types` — в git» не затронуто.
