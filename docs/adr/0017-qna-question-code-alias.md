# ADR 0017 — код `Q-MON-089` восстанавливается алиасом

- **Статус:** принято
- **Дата:** 2026-08-09
- **Источник:** Executable Rules Registry v1.7 — `AQ2-001`, `CQA-054`, `CQA-055`;
  All Questions and Answers Registry v1.2 — строки №247, №248, №334, №367

## Контекст

Q&A-реестр v1.2 хранит 444 строки под 410 кодами вопросов. Повторы там —
не дефект: 30 кодов встречаются больше одного раза, потому что вопрос
переформулируется в следующем раунде. Ранние строки цепочки помечены
«Изменен последующим ответом и переформирован автоматически», последняя —
«Закрыт».

28 цепочек из 30 устроены именно так. Две — нет:

| Код         | Строки     | Статусы              | Что не так                                       |
| ----------- | ---------- | -------------------- | ------------------------------------------------ |
| `Q-MON-083` | №248, №367 | «Закрыт», «Закрыт»   | две **разные** темы под одним кодом, обе закрыты |
| `Q-MON-082` | №247, №334 | «Изменен», «Изменен» | закрывающей строки под этим кодом нет            |

Executable Rules v1.7 при этом внутренне непротиворечив:

| Правило   | Вопрос      | Тема                                         |
| --------- | ----------- | -------------------------------------------- |
| `CQA-054` | `Q-MON-082` | каких заражённых удалять при снижении лимита |
| `CQA-055` | `Q-MON-083` | серии действий «Мёртвого вестника»           |
| `AQ2-001` | `Q-MON-089` | относительная «новизна» заражений            |

Строка №367 Q&A-реестра несёт текст вопроса, **дословно** совпадающий с
названием `AQ2-001`, и ответ, **дословно** совпадающий с его «Итоговым
алгоритмом» (`infectionOrder`, сортировка целей по UUID, сохранение `newLimit`
записей с наибольшим номером, уничтожение всех при `newLimit=0`). Совпадение
сверено программно, а не на глаз.

Кода `Q-MON-089` в Q&A-реестре нет ни на одном из пяти листов. `Q-MON-088` —
последний код серии, то есть `Q-MON-089` — следующий свободный номер.

Сам реестр в строке `QA-V12-001` заявляет, что все Question ID из Rules в нём
присутствуют. Это неверно ровно для одного кода.

## Решение

**Строка №367 адресуется кодом `Q-MON-089`.**

Поправка применяется в индексе, а не в строках:

- `generated/spec/qna/questions.json` переносит строку дословно, с
  `Код вопроса: Q-MON-083` — спека остаётся точной копией артефакта;
- `generated/spec/qna/questions-by-code.json` получает `Q-MON-083 → [248]` и
  `Q-MON-089 → [367]`;
- `QuestionCode` — 411 литералов;
- алиас объявлен **одной именованной константой** в `tools/import/qna.ts`
  со ссылкой на этот ADR.

Область решения — только этот случай. Появится второе расхождение — новый ADR,
а не пополнение таблицы.

## Обоснование

Спор между артефактами разрешён по [ADR 0003](0003-source-of-truth-order.md):
Executable Rules — уровень 4, Q&A-реестр — уровень 6. Старший источник
выигрывает.

Содержание решения при этом не восстанавливается и не додумывается: оно есть в
обоих артефактах и совпадает дословно. Спорна только метка.

Отвергнутые альтернативы:

| Вариант                                 | Почему отклонён                                                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Исправлять код прямо при импорте        | `generated/` перестаёт быть дословной копией поставки. Прецедент, по которому конвейеру позволено переписывать содержимое read-only артефакта, дороже пользы |
| Оставить `Q-MON-089` неразрешимым       | Решение №367 остаётся адресуемым только под конфликтующим кодом, а потребитель, спросивший `Q-MON-083`, получает два несвязанных решения                     |
| Ввести общий механизм поправок к данным | Снимает обязательный ручной разбор со **следующего** расхождения. Разбор здесь занял час и нашёл коллизию, которую механизм бы скрыл                         |

## Последствия

- Импорт обязан **падать**, если: в реестре появится собственный `Q-MON-089`;
  строка №367 перестанет совпадать с `AQ2-001` дословно; коллизий кодов станет
  больше одной. Алиас без этих проверок превращается в тихую подмену.
- `Q-MON-082` остаётся цепочкой без закрывающей строки. Связь
  `Q-MON-082 → Q-MON-089` **не моделируется**: в артефактах она не объявлена,
  колонка «Основание статуса / поздние вопросы» у обеих строк пуста. Вывести её
  можно только по смыслу текста — это догадка, запрещённая
  [CLAUDE.md](../../CLAUDE.md), раздел 4. Аномалия фиксируется в `meta.json`.
- Инвариант цепочек проверяется по исправленным кодам, с одним именованным
  исключением — `Q-MON-082`.
- Контрольные величины: 444 строки, **411** кодов вопросов.
- В кросс-проверке ссылок `Q-MON-089` перестаёт быть исключением. Там остаётся
  единственное — `USR-2026-07-30-WEB-001`, токен пользовательского решения в
  колонках `Source Question IDs`, не являющийся кодом вопроса.
- Расхождение остаётся в артефакте. Это вопрос к его автору; до ответа
  действует этот ADR.
