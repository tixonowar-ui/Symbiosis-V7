# Проверки CI

Windows job `verify` проверяет установку зависимостей, артефакты, типы,
линтер, формат, импорт, трассируемость, Vitest, кросс-реестровые связи и
production E2E. Импорт выполняется до тестов: им нужны изображения и seed,
которых нет в Git.

## Трассируемость

`npm run traceability:verify` выполняется и в локальном `npm run verify`, и
в CI после импорта. Устаревший `docs/TRACEABILITY.md` или расхождение между
источниками и спецификацией останавливает проверку. Изменив покрытие,
перегенерируйте матрицу командой `npm run traceability` и включите её в PR.

## Воспроизводимость всего вывода

```bash
npm run import:verify
```

Команда запускает два последовательных импорта и сравнивает относительные
пути и SHA-256 каждого файла `generated/`. В сравнение входят `spec`, `types`,
игнорируемые Git изображения в `media` и SQLite в `seed`. Добавленный,
исчезнувший или побайтово изменившийся файл приводит к отказу с указанием пути.
Это проверка одинакового вывода при неизменных входах и установленных версиях
зависимостей, предусмотренная ADR 0015. Каталог не очищается: проверяется
повторный импорт в текущем рабочем дереве.

После неё CI отдельно проверяет `git status --porcelain -- generated/`.
Два одинаковых результата ещё не доказывают, что актуальный вывод включён в
коммит. Для изменений импортера пересоберите вывод и включите изменения
отслеживаемых файлов в PR.

## Пустые тестовые прогоны

`npm test`, `npm run test:coverage` и `npm run test:e2e` завершаются ошибкой,
если runner не нашёл тестов. Фиксированного ожидаемого количества нет:
набор может расти, но исчезновение всего набора не считается успехом.
`test:e2e` сначала собирает production-клиент.

## Диагностика E2E и повторных попыток

В CI остаётся одна повторная попытка. Если первая попытка упала, а повтор
прошёл, Playwright отмечает тест как `flaky`. Такой прогон пока остаётся
зелёным; статус не означает, что нестабильность устранена.

HTML-отчёт сохраняется при успешном и неуспешном E2E-шаге. Для каждой
неудачной попытки сохраняются trace и screenshot, включая первую попытку
перед успешным повтором. В CI GitHub reporter также выводит диагностику
в интерфейс Actions.

1. Откройте запуск CI → артефакт `e2e-diagnostics-<номер попытки workflow>`.
2. Скачайте и распакуйте его. Срок хранения — 14 дней.
3. Откройте отчёт командой `npx playwright show-report <путь>/playwright-report`.
4. Выберите `Flaky` или `Failed`, затем нужную попытку, trace и screenshot.

Отдельный trace можно открыть командой
`npx playwright show-trace <путь>/trace.zip`. Локальные результаты находятся
в `reports/playwright-report` и `reports/e2e-artifacts`.

Если job остановился до E2E или был отменён, загрузка диагностик не
выполняется. Ошибка сборки до запуска Playwright может оставить отчёт пустым;
первичная причина в таком случае находится в логе шага E2E.
