# Чеклист ревью

Для Claude как ревьюера. Отсортировано по приоритету: сверху то, что дороже
всего стоит пропустить.

**Экономия внимания — часть задачи.** Всё, что проверяет CI, я не перепроверяю.
Ниже явно разделено, где машина справляется, а где нужно читать код.

---

## Что уже проверяет CI — не трачу на это внимание

| Проверка                                                  | Чем ловится                           |
| --------------------------------------------------------- | ------------------------------------- |
| Синтаксис, типы, неиспользуемые переменные                | `typecheck`, `lint`                   |
| Форматирование, отступы, кавычки                          | `format:check`                        |
| Концы строк, BOM                                          | `.gitattributes` + Windows-раннер     |
| Дрейф артефактов                                          | `checksums:verify`                    |
| Недетерминизм конвейера                                   | шаг «Pipeline output is reproducible» |
| Дубликаты ID, битые ссылки, осиротевшие записи, формат ID | `validate`                            |
| Падающие тесты                                            | `npm test`                            |
| Немаркированные `TODO` / `STUB`                           | job `markers`                         |
| Раздутый PR                                               | `pr-size.yml`                         |

Если CI красный — я не читаю код. Возвращаю с указанием упавшего шага.

## 1. Границы (стоп-сигналы)

Проверяю первым. Нарушение — отказ без обсуждения деталей реализации.

- [ ] `artifacts/` не изменён. Даже «незначительно»
- [ ] `generated/` изменён только прогоном импорта, не руками
- [ ] `CHECKSUMS.sha256` не перегенерирован без новой поставки
- [ ] Существующая проверка не ослаблена ради прохождения задачи —
      особенно стражи ADR в `tools/import`
- [ ] Принятый ADR не отредактирован по существу
- [ ] Зависимость не добавлена без ADR

## 2. Выдуманные данные

Главный риск проекта. CI это **не ловит**.

- [ ] У каждой новой числовой константы есть источник в артефакте —
      реестр, лист, ID. Число без источника не проходит
- [ ] Не появилось «правдоподобного» значения на месте отсутствующего
- [ ] Не появилось `TODO` с выдуманным числом внутри
- [ ] Названия и тексты взяты из артефакта, а не сочинены

Сомневаюсь — спрашиваю, где это в артефакте. Ответ «по аналогии» = отказ.

## 3. Fail-closed

CI ловит падающий тест, но не ловит тихую ветку «по умолчанию».

- [ ] Неизвестное значение приводит к отказу, а не к обработке по умолчанию
- [ ] В отказе названо то, что именно не распознано
- [ ] Нет `catch`, который глотает ошибку
- [ ] Нет `?? defaultValue` там, где отсутствие значения — это ошибка
- [ ] Нет `switch` без явного отказа в `default`

## 4. Тесты доказывают, а не сопровождают

- [ ] Тест падает, если убрать изменение. Проверяю мысленно, иногда — руками
- [ ] Есть негативный случай, а не только «счастливый путь»
- [ ] Для проекций: тест доказывает, что роль **не** получает лишнего
- [ ] Ожидаемые величины взяты из артефакта, а не списаны с фактического
      вывода кода. Тест, подогнанный под результат, ничего не проверяет
- [ ] Новый страж инварианта покрыт тестом **на срабатывание**

## 5. Трассируемость

- [ ] Реализованная форма ссылается на свой ID атласа в коде и в тесте
- [ ] Тест правила ссылается на ID правила из реестра
- [ ] `docs/TRACEABILITY.md` обновлён, если покрытие изменилось

## 6. Границы слоёв

- [ ] `src/domain` остался чистым: без `fs`, сети, SQL
- [ ] SQL только в `src/persistence`
- [ ] Клиент не принимает игровых решений
- [ ] Зависимости направлены вниз, см. `docs/ARCHITECTURE.md`

## 7. Инкрементальность

- [ ] Diff соответствует задаче. Нет попутного рефакторинга
- [ ] Работающий модуль не переписан «чтобы красивее»
- [ ] Стиль не изменён в файлах, которых задача не касается

## 8. Читаемость

Последний по приоритету — но не пропускаю.

- [ ] Комментарии объясняют «почему», а не «что»
- [ ] Неочевидное решение объяснено рядом с кодом
- [ ] Имена соответствуют соглашениям (AGENTS.md, 5.4)

## Формат заключения

```markdown
## Ревью PR #NN

**Вердикт:** одобряю / нужны правки / отказ

### Блокирующее

<!-- Нумерованно. Файл:строка, что не так, чем это грозит.
     Пусто — значит блокирующего нет. -->

### Стоит поправить

<!-- Не блокирует merge, но лучше сделать сейчас. -->

### На заметку

<!-- Наблюдения без требований. -->

### Проверено

<!-- Что я смотрел глазами сверх CI. -->
```

Правила формулировок:

- Указываю **файл и строку**, а не «в импорте где-то»
- Объясняю, **чем грозит**, а не только что не нравится
- Если требую изменения — говорю, каким я вижу правильный вариант
- Не повторяю то, что уже сказал CI

## Когда отказ, а не правки

- Изменён `artifacts/`
- Ослаблена проверка ради прохождения
- Выдуманное игровое значение
- Полная пересборка модуля вместо точечного изменения
- PR закрывает задачу не тем способом, который описан в issue,
  и это не обсуждалось заранее
