## Что реализовано в #156

- `CHR-026` и `APP-009`: восстановление единственного полного checkpoint.
  Хост доказывает владельца, entity/checkpoint ID, revision/SHA, текущую строку
  и builder equality. Повреждённая полная версия даёт диагностический экран
  без выдуманного resume и без поиска более старой копии.
- Незавершённый intent хранится отдельно от игрового checkpoint. Только
  доказанный intent с совпавшей базой и без committed receipt может быть
  удалён восстановлением. До commit preview имеет `READY/false`; после
  фактического удаления повреждённого хвоста receipt несёт `CORRUPT/true`
  по ADR 0025. Это успешное восстановление полной версии с диагностикой.
  Producer отдельного intent в этом срезе подключён только к recovery fixture.
- Restore receipt связывает source scope/revisions/binding и точные target
  owner/checkpoint/revisions/form/layers. Клиент принимает меньший creation
  vector только для совпавшей ожидающей команды. Сохранённый диалог CHR-031
  восстанавливается только вместе с подписанной базой CHR-023.
- `CHR-039`: read-only manifest неизменяемых версий веток из проверенной
  истории, выбранная запись, хеши и случайные receipts. Команды активации
  старой ветки нет; возврат связан с конкретным origin/checkpoint.
- Финальное сохранение теперь публикует `CHR-040`. Механика, creation payload,
  checkpoint и исходные receipts остаются неизменны. Правки имени, описания
  и арта хранятся в отдельной append-only истории метаданных.
- `APP-010`: канонический UTF-8 JSON с baseline/provenance и SHA-256 либо
  вариант с новым UUID. Браузер скачивает точные host bytes без повторной
  сериализации и без требования HTTPS Web Crypto. Повтор receipt не вызывает
  второе скачивание. Экспорт не изменяет исходного персонажа.
- Вариант копирует только имя, описание и арт; возраст, пол, масса, механика,
  имущество и броски не переносятся. Первый IDENTITY checkpoint отдельно
  доказывает owner, birth receipt/hash и provisional envelope, затем атомарно
  переводит настоящую строку VARIANT в обычный DRAFT.
- Библиотека публикует только принадлежащие устройству строки. Выбор строки
  использует существующий addressable-route transport с exact signed row;
  URL сам по себе не даёт authority. Обычный `APP-004.localOwnerIdOrNull=null`
  сохранён. Cold-entry CHR-001 получает подписанный полный identity scope.
- Post-save revisions отделены от creation. Scope фиксирует correlation
  конкретного входа, поэтому cache navigation и SAVE_VALID_DRAFT не смешивают
  свои presentation revisions. Receipt, cursor и удаление intent входят в
  одну транзакцию; следующий подтверждённый checkpoint закрывает прежний
  receipt cursor, а чтение и no-op его не закрывают.
- Отдельный доверенный GM fixture проверяет архивный экспорт через APP-010:
  реальную archived campaign copy, owner context и checkpoint provenance.
  Для него доступен только export; player variant, CMP-012 и обычный
  campaign runtime не реализованы этим срезом.

Технические решения описаны в
[ADR 0063](../adr/0063-local-character-recovery-and-export.md), который пока
имеет статус «предложено». Его принятие и окончательные результаты проверок
нужно зафиксировать перед merge.

## Проверки и ревью

- `npm run import` прошёл, tracked generated-вывод не изменился.
- Полный `npm run verify` прошёл: **121 файл / 2198 Vitest-тестов**, типы,
  ESLint, Prettier, трассируемость, контрольные суммы и валидация.
  Лог: `reports/156-verify-root-final.log`.
- Production-сборка и **30/30 Chrome E2E** прошли без retry: 26 прежних
  сценариев, три новых локальных и один GM archive export fixture.
  Лог: `reports/156-e2e-root-final.log`.
- Проверены реальный SQLite reopen с двумя персонажами, обрыв между
  RESTORE commit и доставкой, следующий checkpoint после restore, CHR-031,
  неизменность FINAL, два владельческих контекста и повтор старых EXPORT/VARIANT
  после новой metadata-версии без replacement UUID/bytes и отката cursor.
- Независимое чтение нашло и помогло исправить crash windows, слои,
  replay после metadata и неразличимые одноимённые записи. Reviewer прочитал
  новые модули и изменённые интеграционные пути; тестовый diff — выборочно.
  Объём кода превышает измеренную границу чтения в 6000 строк.
- Свежий независимый `verify`/E2E на окончательном commit и CI фиксируются
  в PR до merge. Целевые проверки не заменяют эти обязательные прогоны.

Артефакты, importer, зависимости, outer protocol, CI и конфигурация проверок
не меняются. SQL-схема расширена forward-only миграцией `0006`. Generated
не редактируется вручную; матрицу трассируемости пересобирает штатный инструмент.
