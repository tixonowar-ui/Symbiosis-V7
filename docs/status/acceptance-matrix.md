# Финальная матрица приёмки

> Снимок: 2026-10-24, исходный HEAD `3635e9b86e4e050a9ff41d80ad6a158064ec8899`.
> Это компактный индекс полной матрицы, а не заявление о готовности продукта.
> Полная матрица получается декартовым произведением обязательных строк ниже на
> объекты машинных каталогов плюс пообъектные доказательства. Тысячи строк
> артефактов здесь намеренно не дублируются.

Обязательный объём задают [ROADMAP M0–M9](../ROADMAP.md),
[вертикальные срезы](../PRODUCT-PLAN.md) и
[приоритет источников ADR 0003](../adr/0003-source-of-truth-order.md). Текущие
структурные счётчики — в [TRACEABILITY](../TRACEABILITY.md), состояние среды — в
[autonomous-checkpoint](autonomous-checkpoint.md).

## 1. Статусы и доказательства

- **НЕ ГОТОВО** — поведение не реализовано либо обязательные проверки и
  доказательства отсутствуют; нулевой прогресс выделяется отдельно.
- **В РАБОТЕ** — есть подтверждённая часть, но объект или сквозной контур ещё не
  принят целиком.
- **ПОДТВЕРЖДЕНО (baseline)** — названный импорт/проверка действительно прошли;
  это не продуктовая приёмка и не статус `ГОТОВО` для связанных механик.
- **ГОТОВО** — ожидаемое поведение объекта и негативные ветки проверены, ссылки
  на код, тест, команду/прогон и результат приложены, обязательные E2E/ручные
  проверки завершены, `npm run verify` зелёный на том же HEAD.

`COVERED` в артефакте означает покрытие спецификацией, не реализацию. Колонки
`implemented`/`tested` в `TRACEABILITY` — структурные индикаторы ссылок, не
самостоятельное доказательство поведения. Упоминание ID в документе или тесте
тоже не закрывает приёмку.

## 2. Как получить статус любого объекта

1. Выбрать объект по ключу из таблицы baseline; ожидаемое поведение читать в его
   записи и связанных ADR/Q&A. Для Q&A `questions-by-code.json` хранит номера
   `№` (1-based), поэтому запись ищется по `№` в `questions.json`, а не по
   нулевому индексу массива.
2. Выполнить `npm run traceability:verify`. Затем применить тот же алгоритм, что
   и [генератор](../../tools/traceability/traceability.ts): `scanRepository()`
   разделяет implementation/tests, `readPublishedFormIds()` читает
   `PRESENTED_FORM_IDS`. Для перехода ключ —
   `JSON.stringify([from,to,kind,trigger])`.

```ts
implemented = isForm
  ? publishedFormIds.has(id)
  : isTransition
    ? scans.implementation.transitions.has(transitionKey)
    : scans.implementation.literals.has(id);
tested = isTransition ? scans.tests.transitions.has(transitionKey) : scans.tests.literals.has(id);
```

`literalLocations`/`transitionLocations` дают файл и строку свидетельства. Для
70 operations и 106 workflow-команд, которых нет в сводке генератора, дополнительно
обязательны регистрация/исполнение соответствующего handler или host contract и
behavior-тесты; одна строка ID недостаточна. Текущий CLI выводит агрегаты, а
пообъектный паспорт строится из указанных множеств без изменения правил.

3. Записать паспорт: `class/key → normative source → implementation evidence →
test evidence → run/environment → status`. Любое отсутствующее обязательное
   звено оставляет `НЕ ГОТОВО` или `В РАБОТЕ`, а не повышает статус по догадке.

## 4. Общий gate выпуска

Продукт **НЕ ГОТОВО**, пока хотя бы одна обязательная строка или объект не имеют
статус `ГОТОВО`. Для кандидата дополнительно обязательны: актуальные
`TRACEABILITY`, `module-map` и `CHANGELOG`; `npm run import && npm run verify`;
зелёный CI; реальные E2E вместо `--pass-with-no-tests`; доказательства
Windows/LAN и portable-прогона. Merge выполняет только владелец репозитория.
