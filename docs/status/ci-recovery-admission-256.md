## Узкая коррекция по ADR 0088

Только campaign occupied-port case получает BODY60000 вместо 30000 мс.
Только missing-extra-tab выполняет тот же `submitOwner()` в существующем hook
60000 мс рядом с ранее принятым rollback-case. Константы имён используются в
заголовках и взаимно исключающих guards. Счётчик сбрасывается на каждом случае,
а обязательная проверка `=== 1` остаётся до publication/preparation. Все остальные
реальные submit выполняются в исходном hook30000. Тело missing-tab и остальные
hooks сохраняют свои бюджеты.

60000 — конечное удвоение прежнего предела, выбранное для двух именованных
отказов. Из него нельзя вывести запас относительно неизвестного exclusive
времени исходного CI. Увеличение бюджета не устанавливает и не исправляет
причину задержки. Проверки данных, replay и cleanup сохраняются. Накопленные
монотонные метки выводятся только при отказе соответствующего случая и позволяют
увидеть порядок фаз после cleanup. Shared fixture не получает диагностический API.

Новый committed SHA проходит отдельные полный clean gate и CI. Предыдущие
результаты и диагностическая пара сохраняются как история измерений.

при успехе не выводились, отпечатки файлов до и после совпали. Вывод и metadata
