# Чистое ядро NPC — техническая поставка #230

#230 выделена из #187 по границе чистых вычислений. Полная приёмка NPC
остаётся в #187/#113. Эти модули сами по себе не добавляют доступный игроку
или мастеру сценарий: существующее приложение их ещё не подключает.

## Что поставляется

| Область                 | Граница результата                                                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Каталоги и DTO          | Source-bound lookup, закрытые входы и явное различие UNSET/ENTERED. Отсутствие ввода не заменяется игровым default.                                                                                                                 |
| Характеристики и состав | Базовые параметры, выбор развития, обычный состав, native/passive profiles и отдельные последствия состава. Вычислитель не создаёт историю операций.                                                                                |
| Навыки                  | Проверка источников, контекстов и учёт приобретений; отдельный расчёт не выдаёт GM полномочия.                                                                                                                                      |
| Здоровье и состояния    | Компоненты HP/life state, моделируемые болезни, unconsciousness, закрытые codecs ран и травм.                                                                                                                                       |
| Начальные травмы        | Принятый #228 current initial state: TORSO сохраняет введённый итоговый HP, HEAD penalty/stun выбираются независимо, активный stun требует точного остатка и календарного evidence. Исторический origin не заменяется новым COMMIT. |
| Инвентарь               | Подготовка и проверка физических предметов и опубликованных weapon profiles; отдельный расчёт выбранной брони с символическими формулами защиты и source modifiers.                                                                 |
| Листы                   | Builders/readers явно поддержанных `NPC_CLEAN_HUMANOID_V1` и `NPC_HUMANOID_V1`; чтение пересчитывает значения по источникам и переданным owning доказательствам.                                                                    |
| Загрузка                | `src/host/npc-catalog.ts` читает существующие поставленные каталоги. Новых маршрутов, wire-команд и registrations нет.                                                                                                              |

Чистый domain не выполняет SQL, сеть, RNG или генерацию идентификаторов.
Резервирование ID, подтверждение полномочий, проверка происхождения evidence
и атомарная запись принадлежат будущей host/persistence интеграции #187.
Успешный codec или совпавший hash сами по себе таких доказательств не создают.

Броня учитывается по явному набору предметов. Полный костюм вносит собственные
параметры один раз и защиту по охватываемым зонам; отсутствующая физическая
защита остаётся отсутствующей. Совместимость требующих её слоёв должна быть
отдельно подтверждена хостом. Компонент не выполняет бросок защиты и не
превращает список предметов в разрешение носить любое сочетание.

## Что остаётся сделать

Компоненты не означают, что любая их комбинация уже поддержана полным листом.
Часть входов намеренно имеет `never` или явный `NOT_YET_SUPPORTED`; неизвестное
или ещё не реализованное состояние не превращается в успешный частичный NPC.
Полная композиция symbiont interactions, источникоспецифические initial states
и интеграция всех компонентов в экранный wizard остаются в #187.

Открытые источниковые вопросы #224/#226/#227 не решаются догадками. Отдельные
NPC/monster passive components не завершают создание врагов #188 и не вводят
новый способ бросков или расходования one-shot прав.

До закрытия #187 обязательны реальные controls каждого принятого шага,
единственная GM authority, attempts и immutable versions, V1 → история → N+1,
art, atomic checkpoint/receipt, replay/lost reply, restart, privacy и production
browser acceptance. #230 не заменяет ни один из этих пунктов.

## Проверка поставки

Owning suites используют реальные поставленные source rows, проверяют расчёты,
точные границы и отказ неизвестного/неполного ввода. Для окончательного SHA
сохраняются независимое semantic review по областям, новый чистый полный
пятиэтапный прогон, CI и проверка дерева после squash merge. Авторские целевые
проверки не выдаются за эту финальную приёмку.
