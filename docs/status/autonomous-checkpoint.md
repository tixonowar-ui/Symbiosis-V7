- `docs/TRACEABILITY.md` всё ещё показывает неполную реализацию: например,
  18/699 active rules, 4/19 lifecycles, 20/376 forms, 0/66 journeys и 0/2440 QA.
- **Реальных E2E нет.** Playwright настроен, но `tests/e2e` пуст и браузеры не

- **Portable-сборки нет.** `tools/package` пуст; `npm run build` собирает только
  веб-клиент и не является поставкой приложения.
- Финальные authority/privacy/atomicity/reconnect, Windows/LAN и packaging
  приёмки не закрыты. Их обязательные проверки перечислены в
  [acceptance-matrix](acceptance-matrix.md).
- Этот checkpoint не разрешает merge и не меняет защиту `main`.

## 4. Доступный способ автономной работы

- Работа ведётся в локальном clone; состояние и артефакты проверяются локально.
  GitHub MCP доступен для issue, веток и PR.
- Для каждой задачи используется отдельная ветка `codex/<issue>-<кратко>` и
  отдельный PR. Одна ветка — один агент; чужие ветки не изменяются.
- Владелец разрешил привлекать субагенты. Их результат проверяется и интегрируется
  ответственным агентом текущей ветки; субагент не получает права merge.
- `artifacts/**` read-only, `generated/**` не редактируется вручную, принятые ADR
  не переписываются по существу. Для #135 новый ADR 0048 создаётся вместе с
  реализацией, а не подменяется предположениями.
- **Между сессиями работа не выполняется без нового запуска.** Нет фонового
  агента, который продолжает разработку сам. При новом запуске сначала читаются
  этот checkpoint, матрица, issue и `git status`; работа возобновляется с явно
  подтверждённого следующего шага.
