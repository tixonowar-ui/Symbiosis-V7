# Symbiosis V7 — правила проекта

Offline-first LAN-приложение с единственным авторитетным хостом.
Роли: `player`, `gm`, `system`. Целевая платформа — Windows 10 (1809+) / 11 x64.

Этот файл задаёт правила работы с кодовой базой. Он обязателен к соблюдению и
имеет приоритет над привычками и умолчаниями.

---

## 1. Источники правды и их приоритет

Документы проекта стоят выше исходных артефактов разработки. Внутри артефактов
действует порядок, объявленный самим атласом v1.2 (см.
[docs/adr/0003-source-of-truth-order.md](docs/adr/0003-source-of-truth-order.md)).

| #   | Источник                                            | Что решает                                                                                                        |
| --- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 1   | `docs/adr/`                                         | решения проекта; перекрывают всё нижележащее                                                                      |
| 2   | `docs/`                                             | прочая проектная документация                                                                                     |
| 3   | `artifacts/registries/…Delivery_Manifest_v1.2.xlsx` | состав поставки, совместимость, границы замороженных артефактов                                                   |
| 4   | Старшие предметные реестры                          | Executable Rules, Character/Skills/Symbionts, Items, Effects/Diseases, Canonical Bestiary, Default Sentient Enemy |
| 5   | Спецификации реализации                             | Soundtrack Registry (звук), `artifacts/atlas/` Web UI Screen Atlas v1.2 (UI)                                      |
| 6   | All Questions and Answers Registry                  | только если решение ещё не материализовано в старшем реестре                                                      |
| 7   | `artifacts/packs/` Runtime Pack                     | только точные системные шаблоны и арт — **никогда** не источник новых правил                                      |
| 8   | Cross-Registry Audit Report                         | свидетельство консистентности, **не** самостоятельный источник механик                                            |

Если два источника противоречат друг другу — выигрывает тот, что выше. Если
противоречие внутри одного уровня — остановиться и спросить.

## 2. artifacts/ — read-only

Каталог `artifacts/` содержит поставленные артефакты и **изменять его
запрещено**. Единственный файл, который туда пишется инструментом, —
`artifacts/CHECKSUMS.sha256`.

```bash
npm run checksums:verify
```

Эта команда обязана проходить перед каждым коммитом. Если она падает —
артефакт был изменён или подменён, и это баг, а не повод перегенерировать
манифест.

## 3. generated/ — только вывод конвейера

`generated/` целиком производится инструментами из `tools/import`. **Руками не
править.** Любая правка будет затёрта следующим прогоном.

- `generated/spec`, `generated/types`, `generated/seed` — в git
- `generated/media` — **не** в git (крупные бинарные файлы, пересобираются)

Нужно изменить содержимое `generated/` — меняется конвейер или артефакт-источник,
но не результат.

## 4. Не выдумывать игровые данные

Игровые формулы, числовые значения, пороги, ограничения, названия и тексты
**не придумываются**. Всё берётся из артефактов.

Нет данных в артефактах — **остановиться и спросить**. Не подставлять
правдоподобное значение, не оставлять `TODO` с выдуманным числом, не
экстраполировать по аналогии с соседним правилом.

## 5. Fail-closed

Неизвестная команда, workflow, тип эффекта или переход **отклоняются**.

- Никаких generic fallback
- Никакого «оно похоже на X, обработаем как X»
- Никакого молчаливого no-op

Отказ должен быть явным, с указанием того, что именно не распознано.

## 6. Трассируемость до атласа

Каждая реализованная форма **ссылается на свой ID из атласа** — и в коде, и в
тестах. ID — это `APP-001`, `CMB-014` и т. п.

## Команды

```bash
npm run verify
```

Полная проверка: контрольные суммы → типы → линтер → формат → тесты.

| Команда                           | Что делает                               |
| --------------------------------- | ---------------------------------------- |
| `npm run import`                  | `artifacts/` → `generated/`              |
| `npm run checksums`               | пересчитать `artifacts/CHECKSUMS.sha256` |
| `npm run checksums:verify`        | проверить артефакты на дрейф             |
| `npm run typecheck`               | `tsc` по node- и web-проектам            |
| `npm run lint` / `lint:fix`       | ESLint                                   |
| `npm run format` / `format:check` | Prettier                                 |
| `npm test`                        | vitest, юнит-тесты                       |
| `npm run test:e2e`                | Playwright, e2e                          |

## Соглашения по коду

- TypeScript strict, ESM, Node 24 LTS (см. `.nvmrc`)
- Юнит-тесты лежат рядом с кодом: `src/**/*.test.ts`
- Кросс-слойные тесты — `tests/integration`, e2e — `tests/e2e`
- Импорт общего кода через `@shared/*`, сгенерированного — через `@generated/*`
