# src/persistence — правила слоя

Читать вместе с корневым [CLAUDE.md](../../CLAUDE.md).

Хранилище на SQLite через `better-sqlite3`. Драйвер **синхронный** — это
осознанный выбор (см. [ADR 0002](../../docs/adr/0002-stack.md)), а не недосмотр.
Не оборачивать вызовы в промисы ради единообразия.

## Границы

- Обращаться к БД можно **только** отсюда. `src/domain` не знает про SQL,
  `src/host` не пишет запросы напрямую.
- Слой не содержит игровых правил. Он хранит и отдаёт, но не решает.
- Единственный процесс-писатель — хост. Приложение offline-first и
  однохостовое, поэтому конкурентная запись из нескольких процессов не
  поддерживается и не эмулируется.

## migrations/

- Миграции нумерованные, применяются по порядку, **только вперёд**.
- Уже применённая миграция неизменяема. Ошибку исправляет следующая миграция.
- Каждая миграция идемпотентна по факту применения: повторный запуск на
  актуальной схеме ничего не делает.
- Схема выводится из реестров и `generated/spec`, а не придумывается.

## Seed

`generated/seed/` — вывод `tools/import`, в git. Пересобирается из артефактов,
руками не правится. Локальные файлы БД (`*.sqlite`, `*.db`) в git **не
попадают** — см. `.gitignore`.

## Тесты

`src/persistence/**/*.test.ts`. Работать с БД в памяти (`:memory:`), не
создавать файлы в репозитории. Тесты на миграции проверяют путь с нуля до
актуальной версии.
